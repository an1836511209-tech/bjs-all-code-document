# 投资人报告生成部署方案

日期：2026-11-01。依据当前仓库里的 `deploy/environments/prod`、`compose.yaml`，以及 `docs/change-notes`、`docs/Production-deployment-issues` 里已经发生过的线上问题。

2026-10-19 的旧文只覆盖投资人报告两个容器和 `/dev`。当前镜像里已经有工作台、一页纸和三件补充数据工具。本文分成两部分，配置基线相同：

- **第一部分**是一台新机器从 0 到 1。
- **第二部分**是已经按旧文跑起来的生产目录，从现在的状态补到当前版本。

口令、网关 token 和业务密钥只放在服务器上的 `runtime.env` 与两份 YAML 里。本文只写变量名和当前已经定下来的地址、限额。

test / UAT 的 DMP 模拟器和 `compose.dmp-mock.yaml` 不进这台生产机。生产 YAML 没有 `mode: mock`；进程若发现 mock 地址或 mock 密钥，会直接拒绝启动。

## 当前配置基线

两部分都用这一套，不另起数据库、队列或编排。

运行目录固定为：

```text
/data/hiagent/bjs-investment-report-agent-main
```

所有命令都在这个目录执行。Compose 的相对路径相对它。

```text
浏览器
  -> 现有 Nginx
       -> 127.0.0.1:5129 -> report-agent:8000     唯一对外进程
            /console/          工作台静态页，打进镜像
            /api/              提交、SSE、下载、会话、附件状态
            |
            +-- 宿主机 workspaces/                uid 10001，API 与附件 worker 共用
            |
            +-- workbook-worker                   默认不部署；启用附件时才加，无端口
            |
            +-- data-mcp:8001                     只在 Compose 网络内
                 resources/                       uid 10002 只写索引目录

MySQL 业务库 bjs-investment-report-agent     任务 / run / artifact；附件表默认先建好、功能仍关闭
MySQL 检查点库                               默认不建；只给打开开关之后新建的一页纸
MinIO 桶 bjs-file                            Word / Excel 对象；浏览器不直连
模型、OCR、HiAgent、DMP、企查查、北交互联官网
```

| 进程 | 镜像 | 端口 | 副本 |
| --- | --- | --- | --- |
| `data-mcp` | `bjs-data-mcp:0.1.0` | 容器 8001，宿主机不发布 | 1 |
| `report-agent` | `bjs-report-agent:0.1.0` | 容器 8000，只绑定 `127.0.0.1:5129` | 1 |
| `workbook-worker` | 与 `report-agent` 同一镜像 | 无 | 默认 0 |

主报告在这一个 API 进程里执行。发布、扩容都保持这一条。Redis 的变量留在 `runtime.env` 里，因为配置模型要求这些字段；当前代码不用 Redis 做队列、锁或会话。

两个镜像必须同一次 `build`。契约在镜像内的 `/app/contracts/mcp`，一共九份，运行目录里没有这层，也不要另挂一份旧目录盖住它。其中 `query_track_labels.json` 只接受 `data.tags`。旧 data-mcp 若仍在 `data` 里返回 `source`、`local_recall_used`，新 report-agent 会在标签步骤校验失败；工具名还在，不代表契约一致。`export_matched_institutions.json` 只给附件 worker 用，不要写进 `enabled_tools`。

一页纸模板在 report-agent 镜像里：`skills/one-pager/assets/产权模板.docx`、`增资模板.docx`。缺文件时渲染报 `one-pager template not found`。它们不在宿主机 `resources` 下。意识形态词表同样在镜像内。

`deploy/environments/README.md` 里「必须恰好五个工具」是旧说明。当前 prod 是五个标准工具，再加上 `query_company_registry`、`search_company_web`、`query_cbex_listing_financials`。不要为了和那份说明一致把这三件删掉。投资报告和一页纸开工前都会向 Data MCP 要已启用工具；工商查询不在这道检查里，网页搜索和北交互联财务在。旧 data-mcp 没有后两件时，新 report-agent 一提交就报未就绪。

仓库根目录的 `compose.yaml` 同时给本机 Docker 联调用：它把 5128、5129 发布到所有网卡，也没有附件 worker。服务器上的文件按本文第 1.3 节改。把仓库文件原样盖回服务器，5128 会重新对业务网打开。`runtime.env` 里的 `REPORT_AGENT_CONFIG`、`DATA_MCP_CONFIG` 是仓库根目录相对路径；Compose 的 `environment` 会改成容器内绝对路径。迁移和启停都走 Compose，不要在服务器上按 `runtime.env` 里的相对路径直接起进程。

`docker compose down` 只停容器。不删远程 MySQL、MinIO，也不删宿主机 `workspaces`。

## MySQL 这次要改什么

要改。库是 `runtime.env` 里的业务库 `bjs-investment-report-agent`（`10.254.19.160:3306`）。API 启动不建表，也不改表。新镜像替换容器之前，先执行一次迁移。已有任务行、报告行不删除、不改写。

2026-10-19 上线时业务库里已有四张表：`report_agent_tasks`、`report_agent_sessions`、`report_agent_runs`、`report_agent_artifacts`。这次在这四张表上的变更只有一处：

| 脚本 | 对象 | 已上线的库要不要动 |
| --- | --- | --- |
| `001_task_run_artifact.sql` | 上面四张表的 `CREATE TABLE IF NOT EXISTS` | 表已在则整段跳过。它不会给旧表加列 |
| `002_run_skill_columns.sql` | `report_agent_runs` 增加可空列 `skill_name`、`skill_route` | **要。** 新镜像在报告结束时执行的 `UPDATE` 带这两列。缺列时任务能开始，结束落库失败 |
| `003_institution_workbook.sql` | 新建 `report_agent_auxiliary_jobs` | **同一次一起建。** 投资机构匹配表默认仍关闭，现有任务不写这张表。表不在时，以后打开 worker 会直接失败 |

`001` 的新建表语句里现在也写了 `skill_name`、`skill_route`。旧库的表是当时那版 `001` 建的，没有这两列。`CREATE TABLE IF NOT EXISTS` 看到表已存在就什么都不做，所以旧库必须靠 `002` 的 `ALTER TABLE`。迁移命令遇到「列已存在」（MySQL 1060）会跳过该语句，重复执行是安全的。

投资人内部库 `touziren` 里的 `投资人权重全量`、`投资人信息全量` 是 Data MCP 读取的数据，这次不改结构。

一页纸检查点不建在业务库里。默认关闭，这次升级不执行。以后若打开，先另建空库，再跑带 `--no-deps` 的 `report-agent-db-migrate --checkpoints --apply`，由检查点组件在那个库里自己建表。

业务库账号需要 `CREATE`、`ALTER`、`INDEX`、`REFERENCES`。只有增删改查权限时，迁移会报 1142。已有行不需要业务账号有 `DROP`。

在运行目录、新镜像已经 `docker load` 之后执行。`--no-deps` 让这次只连 MySQL，不要为了等 data-mcp 健康而先去重建上市公司索引：

```bash
cd /data/hiagent/bjs-investment-report-agent-main
docker-compose --env-file deploy/environments/prod/runtime.env run --rm --no-deps \
  report-agent report-agent-db-migrate --apply
```

成功时会打印 `applied N Report Agent schema statements`。旧库上 `001` 的建表被跳过，实际落下去的是 `002` 的两列和 `003` 的新表。列已经加过时，输出里会有 `skipped ... existing columns`。

读取旧 run 用的是 `SELECT *`，缺这两列时查询仍能返回。报告结束时的 `UPDATE` 会写 `skill_name`、`skill_route`。所以新 report-agent 必须等这条迁移成功后再启动，否则任务能开始，结束时落库失败。

在业务库上核对：

```sql
SHOW COLUMNS FROM report_agent_runs LIKE 'skill_name';
SHOW COLUMNS FROM report_agent_runs LIKE 'skill_route';
SHOW TABLES LIKE 'report_agent_auxiliary_jobs';
```

三行都有结果再重建 `report-agent`。第一部分第 1.4 节、第二部分第 2.4 节都用这一条命令，不要另写 SQL 手工改表。

## 第一部分：新机器从 0 到 1

外部依赖先就绪，本机不启动它们：MySQL 业务库、MinIO 桶、模型、OCR、Gotenberg、Tika、Embedding、Rerank、HiAgent、DMP 网关、企查查。data-mcp 还要能访问 `https://api.qichacha.com`、`https://open.bigmodel.cn` 和 `https://otc.cbex.com`。北交互联是这次新增的出站；企查查和智谱若旧环境已经在做项目画像，防火墙里通常已经有。工作台里的 Word 预览由 report-agent 用环境变量 `GOTENBERG_URL` 转 PDF，转换失败时退回原文件，报告本身仍可以下载。Redis 地址按现有 `runtime.env` 填写即可。

业务库账号需要能建表。检查点库和附件 worker 留到第 1.6 节，默认不做。

### 1.1 构建机打包

在有源码、能访问构建网络的机器上，从要发布的 commit 构建。镜像构建使用仓库里的 prod env，只为了让 Compose 解析到 `APP_ENV` 和子网；运行时配置仍以服务器上挂载的文件为准。

```bash
git rev-parse HEAD
git lfs pull
test "$(wc -c < resources/reference_data/data_mcp/listed_peer_index/vectors.bin)" -eq 123346944
test "$(wc -c < resources/reference_data/data_mcp/listed_peer_index/present.bin)" -eq 30114
test -s resources/reference_data/data_mcp/listed_peer_index/manifest.json

docker compose --env-file deploy/environments/prod/runtime.env build
docker save -o bjs-investment-report-images.tar bjs-data-mcp:0.1.0 bjs-report-agent:0.1.0
docker image inspect --format '{{.RepoTags}} {{.Id}}' bjs-data-mcp:0.1.0 bjs-report-agent:0.1.0
```

data-mcp 镜像构建需要仓库根目录 `README.md`。`.dockerignore` 已保留它，以及两个包的 README。report-agent 镜像必须包含 `frontend/`，否则 `/health` 里 `console` 为 `missing`，工作台 404。

运行目录包只带这些，不要带整个仓库、`.runtime`、虚拟环境或 `*.tar`：

```text
compose.yaml
deploy/environments/prod/runtime.env
deploy/environments/prod/data-mcp.yaml
deploy/environments/prod/report-agent.yaml
resources/reference_data/data_mcp/
workspaces/          # 空目录即可
```

把两条 Image ID 和 commit 写进随包的 `RELEASE.txt`。

### 1.3 放到服务器之后先改 Compose

相对仓库 `compose.yaml`，服务器文件改这四处，其余安全参数保持不动：

- 删除 `data-mcp` 的 `ports`。Agent 使用 `http://data-mcp:8001/mcp`。
- `report-agent.ports` 改为 `"127.0.0.1:5129:8000"`。
- 把 report-agent 的 `/tmp` tmpfs 从 `size=128m` 改为 `size=512m`。上传上限是 100 MB，临时文件落在这块 tmpfs 上。128 MB 放得下一份接近上限的材料，放不下同一时刻的第二份，请求会在业务校验前失败。
- 默认不要写 `workbook-worker`。启用附件时再按第 1.6 节加。

report-agent 上现有的 `read_only`、`security_opt`、`cap_add`、`pids_limit: 256`、`mem_limit: 4g`、`cpus: 2.0`，以及 data-mcp 的健康检查、prod YAML 只读挂载，都保留。

### 1.4 导入并启动

服务器上若只有 `docker-compose` 命令，下面都用它。已安装 Compose 插件时写成 `docker compose`。两种都要带 `--env-file`。

```bash
docker load -i bjs-investment-report-images.tar
docker image inspect --format '{{.RepoTags}} {{.Id}}' bjs-data-mcp:0.1.0 bjs-report-agent:0.1.0

cd /data/hiagent/bjs-investment-report-agent-main
mkdir -p workspaces resources/reference_data/data_mcp/listed_peer_index
sudo chown 10001:10001 workspaces
chmod -R a+rX resources
sudo chown -R 10002:10002 resources/reference_data/data_mcp/listed_peer_index

docker-compose --env-file deploy/environments/prod/runtime.env config --quiet
docker-compose --env-file deploy/environments/prod/runtime.env run --rm --no-deps \
  report-agent report-agent-db-migrate --apply
docker-compose --env-file deploy/environments/prod/runtime.env up -d
docker-compose --env-file deploy/environments/prod/runtime.env ps
```

这条命令就是上一节「MySQL 这次要改什么」。空库会建齐四张业务表、两列技能字段和附件队列表。API 启动不建表。附件表建好不等于功能打开。检查点不要放进这一步。

确认容器 Image ID 等于本次 `docker image inspect` 的 ID。

### 1.5 Nginx 与用户入口

5129 只监听本机，5128 不监听宿主机。业务只通过现有 Nginx 进入。

用户入口：

```text
https://<现有域名>/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/console/
```

页面加载后，地址栏改成 `/console/`。这一次打开里，接口仍请求 `/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/api/...`，由应用剥掉前缀。用户若把地址栏里的 `/console/` 存成书签，下一次接口走不带前缀的 `/api/`。所以三处都要反代，`proxy_pass` 后面不接路径：

```nginx
location /m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/ {
    client_max_body_size 120m;
    proxy_pass http://127.0.0.1:5129;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    gzip off;
    proxy_read_timeout 3600s;
}

location = /console {
    return 301 /console/;
}

location /console/ {
    proxy_pass http://127.0.0.1:5129;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_cache off;
}

location /api/ {
    client_max_body_size 120m;
    proxy_pass http://127.0.0.1:5129;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_cache off;
    gzip off;
    proxy_read_timeout 3600s;
}
```

应用上传上限是 100 MB。代理用 120 MB，给 multipart 边界留余量。`location /console/` 匹配不到不带斜杠的 `/console`，所以单独做 301。

`/api/runs/{run_id}/events` 是 SSE，约 15 秒一条注释心跳。缓冲开着时，长报告的事件流会在代理处停住。`proxy_read_timeout` 大于单次运行上限 1800 秒，这里用 3600 秒。

| 路径 | 作用 |
| --- | --- |
| `/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/console/` | 发给用户的入口 |
| `/console/` | 地址栏改写后的工作台。`/console` 会 307 到这里 |
| `/console/assets/` | 页面脚本和样式，来自镜像，URL 带版本号 |
| `/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/api/` 与 `/api/` | 提交、事件流、会话、下载、附件状态 |
| `/health` | 只给本机验收 |
| `/dev`、`/v1/ai-service/investment` | 旧调试页和干净路径。新入口用上面的工作台地址 |

标题接口 `/api/conversations/title` 限 60 秒，失败就用首句做标题。它超时不代表报告失败，也不要为此去改主模型的 600 秒超时。

会话删除只在工作区写入 `deleted_at`。上传材料、已发布文件和 MySQL 行都还在。

下载由 Report Agent 读 MinIO 再返回。Word 和 Excel 都在 `/api/` 下面。

### 1.6 两项默认关闭的能力

投资报告、一页纸里的业务类型卡片、工商名称补正、北交互联项目选择、非优质信息展示确认，都随当前 report-agent 镜像和已经写好的三件 MCP 工具工作。它们不需要检查点库，也不需要附件 worker。北交互联候选选择、风险展示确认没有新的数据库表。

下面两项仍保持关闭，直到单独验收。

#### 一页纸检查点

只影响打开开关之后新建的一页纸任务。已有任务保持原路径。关掉开关也不会把已经建了检查点的任务退回去。投资报告不连这个库。容器重启后，未建检查点的任务不会从工具步骤续上。

1. 在同一台 MySQL 上建空库，例如 `bjs_report_agent_checkpoints`。库名不要用 `bjs-investment-report-agent`。
2. 在 prod `runtime.env` 增加 `REPORT_AGENT_CHECKPOINT_DATABASE`，值为这个库名。
3. YAML 里开关仍是 false 时先迁移：

```bash
docker-compose --env-file deploy/environments/prod/runtime.env run --rm --no-deps \
  report-agent report-agent-db-migrate --checkpoints --apply
```

4. 输出为 `one-pager checkpoint schema migrated` 后，再在 `service` 下写入 `one_pager_checkpoints: true`，只重建 report-agent。
5. 用一条新的一页纸任务验收：卡片暂停后刷新，仍停在同一题。

专用库缺失，或把它配成业务库时，新一页纸会报配置错误，不会自动从头跑。始终只跑一个 API。确认旧容器已经退出，再启动新的。

#### 投资机构匹配表

Word 先交付。Excel 由单独的 worker 稍后写入，失败不改原报告状态。当前 prod YAML 没有这段，页面上的开关保持未启用。

1. 业务库已有 `report_agent_auxiliary_jobs`。第 1.4 节的 `--apply` 已包含它。只补这张表时：

```bash
docker-compose --env-file deploy/environments/prod/runtime.env run --rm --no-deps \
  report-agent report-agent-db-migrate --apply \
  --migration apps/report_agent/migrations/003_institution_workbook.sql
```

这条路径在容器内的 `/app` 下，对应镜像里的文件。

2. data-mcp 镜像必须带 `export_matched_institutions`。这是代码。旧镜像不会因为挂了新 YAML 就出现这个工具。导出固定向 DMP 要第一批 200 家机构，与报告用的 `institution_limit: 30` 是两条请求。
3. prod `report-agent.yaml` 增加：

```yaml
institution_workbook:
  enabled: true
```

4. 在服务器 `compose.yaml` 增加下面的服务，然后只启动它。它和 API 挂同一块 `workspaces`，心跳在 `workspaces/.institution-worker/state/heartbeat.json`。不映射端口，不加 Bubblewrap 的 `cap_add`。

```yaml
  workbook-worker:
    image: bjs-report-agent:0.1.0
    restart: unless-stopped
    env_file:
      - ${BJS_ENV_FILE:-deploy/environments/test/runtime.env}
    environment:
      REPORT_AGENT_CONFIG: /app/deploy/environments/${APP_ENV:-test}/report-agent.yaml
    command: ["python", "-m", "report_agent.entrypoints.institution_workbook_worker"]
    read_only: true
    tmpfs:
      - /tmp:rw,noexec,nosuid,size=128m
    volumes:
      - ./workspaces:/var/lib/report-agent/workspaces
      - ./deploy/environments/prod/report-agent.yaml:/app/deploy/environments/prod/report-agent.yaml:ro
    depends_on:
      data-mcp:
        condition: service_healthy
    pids_limit: 128
    mem_limit: 2g
    cpus: 1.0
```

`enabled: false` 时这个进程会直接退出。第二份 worker 会抢同一条队列和同一把目录锁。API、worker 的环境变量、YAML 和工作区必须相同。

5. `GET /api/features` 里 `enabled` 和 `worker_online` 都为 true。worker 不在时，页面仍允许勾选，并说明启动后才会生成。

## 启动失败时

- `config --quiet` 找不到 env：当前目录不是运行目录，或没带 prod 的 `--env-file`。
- data-mcp 报 data_dir / taxonomy：`resources/reference_data/data_mcp/` 不完整，或被空目录盖住。
- 索引预热很久或失败：`vectors.bin` / `present.bin` 是 LFS 指针或和 `manifest.json` 对不上，或 `listed_peer_index` 对 uid `10002` 不可写。宿主机这三份文件缺任何一份，挂载都会把镜像里的副本盖掉。
- 迁移报 1142：业务库账号没有 `ALTER` 或 `CREATE`。补权限后重新执行带 `--no-deps` 的 `--apply`。
- 迁移命令一直停在 data-mcp 健康检查：命令里漏了 `--no-deps`，索引正在重建。停掉这次 `run`，加上 `--no-deps` 再迁。
- 一页纸报 `one-pager template not found`：report-agent 镜像里没有两份 docx 模板。不要到宿主机 `resources` 里补。
- 一提交就报 Data MCP 未就绪，缺 `search_company_web` 或 `query_cbex_listing_financials`：data-mcp 镜像旧，或两份镜像不是同一次构建。`query_company_registry` 不在这道检查里。
- 标签步骤校验失败，字段涉及 `source` 或 `local_recall_used`：data-mcp 与 report-agent 的契约不是同一版。
- Word 能下载、预览失败：report-agent 容器访问不到 `GOTENBERG_URL`。下载走 MinIO，预览才走 Gotenberg。
- workspace 写入失败：`workspaces` 对 uid `10001` 不可写。API 和附件 worker 都是这个 uid。
- report-agent 报 Data MCP 未就绪：先看 data-mcp 是否 healthy，再确认这次启动带了 prod env。新工具若报未找到，多半是服务器 YAML 的 `enabled_tools` 还没有三件补充工具，或 data-mcp 仍是旧镜像。
- Bubblewrap `Operation not permitted`：把安全参数加回 report-agent。保持 `bubblewrap`。
- 子网冲突：改 `BJS_DOCKER_SUBNET` 后再 `up -d`。避开 `172.16.0.0/12`。
- `/console/` 404 且 health 里 console 为 `missing`：换带 `frontend/` 的 report-agent 镜像。
- 页面在而按钮全部失败：`dev_ui_enabled` 被设成 false。改回 true 并只重建 report-agent。
- 地址栏变成 `/console/` 后接口失败：Nginx 还没有 `/console/` 或 `/api/`，或前缀 location 的 `proxy_pass` 后面多写了路径。
- 进度停在旧事件、本机 `/health` 仍正常：前缀 location 仍开着代理缓冲，或 `proxy_read_timeout` 短于运行时间。
- 附件勾选后一直不生成：看 `/api/features`。`enabled` 为 false 是 YAML 或旧 API 进程；`worker_online` 为 false 是 worker 没起来、没挂同一工作区，或心跳超过 20 秒。
- 一页纸新任务报检查点配置错误：开关已打开，但 `REPORT_AGENT_CHECKPOINT_DATABASE` 为空或等于业务库名。投资报告不依赖这项。
