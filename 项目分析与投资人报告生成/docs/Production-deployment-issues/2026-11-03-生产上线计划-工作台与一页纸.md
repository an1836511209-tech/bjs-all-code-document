### 2.2 随包带上、避免「空目录盖住模板」

仓库 `compose.yaml` 有：

```text
./apps/report_agent/skills/one-pager/assets
  -> /app/.venv/lib/python3.12/skills/one-pager/assets
```

UAT 教训：服务器运行包里没有这两个 docx 时，Docker 会建空目录挂进去，`render_one_pager` 报：

```text
one-pager template not found: .../产权模板.docx
```

正文和审查都能过，就是出不了 Word。今晚必须确认：

- 运行目录包内含  
`apps/report_agent/skills/one-pager/assets/产权模板.docx`  
`apps/report_agent/skills/one-pager/assets/增资模板.docx`
- 或：生产 `compose.yaml` **删掉**该 volume，且镜像内该路径已有文件（当前 Dockerfile 默认**没有**拷到 venv 路径，删挂载前必须先在构建里补齐，否则仍缺模板）

推荐生产当晚策略：**保留挂载 + 包内必带两个 docx**（与 UAT 最终修法一致，风险最小）。

## 3. 上线窗口步骤（按顺序）

总原则：先备份与核对 → 改配置不换镜像 → 迁库 → 换镜像重建（MCP → Agent → **workbook-worker**）→ 核对现有 Nginx 前缀 → 验收。命令一律带  
`--env-file deploy/environments/prod/runtime.env`。目录固定：

```text
/data/hiagent/bjs-investment-report-agent-main
```

### 步骤 A：冻结与备份（约 10–15 分钟）

1. 看是否有运行中的 run；有则等结束或接受重启后需用户重试。
2. 执行部署方案 **2.1** 核对命令，结果记入变更单。
3. 目录外备份现网：`compose.yaml`、`runtime.env`、两份 YAML。
4. 按**正在运行的 Image ID** 导出回退包（部署方案 2.2），勿先 `load` 再想回退：

```bash
docker save -o /data/hiagent/bjs-images-before-20261103.tar <旧 data-mcp ID> <旧 report-agent ID>
```

5. `workspaces/`、`resources/`、MinIO **不删、不空盖**。

### 步骤 B：配置落地（换镜像前）

对照部署方案 2.1 / 2.3 / 1.6，对不上先改文件：

| 检查项 | 期望 |
| --- | --- |
| `APP_ENV` | `prod`（路径是 prod、正文却是 uat 会直接打错环境） |
| `data-mcp.yaml` | `current_env: prod`；DMP `10.3.1.71`（真实，非 mock）；分页机构 0/30、个人 10/100 |
| `report-agent.yaml` | `dev_ui_enabled: true`；`enabled_tools` 含 `query_company_registry`、`search_company_web`、`query_cbex_listing_financials`；**不要**把 `export_matched_institutions` 写进 `enabled_tools`；**打开** `institution_workbook.enabled: true`；`one_pager_checkpoints` 保持关 / 不写 |
| `sandbox.backend` | `bubblewrap`（禁止 `filesystem`） |
| Compose | 无 `data-mcp` 宿主机端口；`127.0.0.1:5129:8000`；`/tmp` tmpfs **512m**；**有** `workbook-worker`（见下）；有一页纸 assets 挂载且宿主机两文件在；**无** dmp-mock |
| 密钥 | `DMP_APP_SECRET`、`API_PLATFORM_TOKEN`、`TRACK_LABELS_SECRET_KEY` 非空；`LLM_MAX_CONTEXT_TOKENS` ≥ 4096 整数 |
| 索引 | `present.bin` 30114；`vectors.bin` 123346944；属主索引目录 uid `10002`；`workspaces` uid `10001` |

`report-agent.yaml` 增加（缺则补；`auto_after_report` 缺省为 true，可不写）：

```yaml
institution_workbook:
  enabled: true
```

服务器 `compose.yaml` 增加 `workbook-worker`（与 API 挂同一 `workspaces`；不映射端口；不加 Bubblewrap `cap_add`）。片段对齐部署方案 1.6，环境文件用生产：

```yaml
  workbook-worker:
    image: bjs-report-agent:0.1.0
    restart: unless-stopped
    env_file:
      - deploy/environments/prod/runtime.env
    environment:
      REPORT_AGENT_CONFIG: /app/deploy/environments/prod/report-agent.yaml
    command: ["python", "-m", "report_agent.entrypoints.institution_workbook_worker"]
    read_only: true
    tmpfs:
      - /tmp:rw,noexec,nosuid,size=128m
    volumes:
      - ./workspaces:/var/lib/report-agent/workspaces
      - ./deploy/environments/prod/report-agent.yaml:/app/deploy/environments/prod/report-agent.yaml:ro
    depends_on:
      data-mcp:
        condition: service_healthy
    pids_limit: 128
    mem_limit: 2g
    cpus: 1.0
```

只起**一份** worker。第二份会抢同一队列和目录锁。API、worker 的 `runtime.env`、YAML、工作区必须一致。`enabled: false` 时该进程会直接退出。

```bash
# 模板目录（若尚无）
mkdir -p apps/report_agent/skills/one-pager/assets
# 确认两个 docx 已在此目录
ls -la apps/report_agent/skills/one-pager/assets/
```

### 步骤 C：导入新镜像

```bash
docker load -i bjs-investment-report-images.tar
docker image inspect --format '{{.RepoTags}} {{.Id}}' bjs-data-mcp:0.1.0 bjs-report-agent:0.1.0
```

**只** `load` **不会替换正在跑的容器。** 标签都是 `0.1.0`，以 Image ID 为准。

### 步骤 D：迁移（新镜像已 load，容器尚未用新层跑业务）

```bash
docker-compose --env-file deploy/environments/prod/runtime.env config --quiet
docker-compose --env-file deploy/environments/prod/runtime.env run --rm --no-deps \
  report-agent report-agent-db-migrate --apply
```

必须带 `--no-deps`，否则会为等 data-mcp 健康去重建索引。业务库核对：

```sql
SHOW COLUMNS FROM report_agent_runs LIKE 'skill_name';
SHOW COLUMNS FROM report_agent_runs LIKE 'skill_route';
SHOW TABLES LIKE 'report_agent_auxiliary_jobs';
```

三行都有结果再往下。缺列时新 Agent 任务能开始、结束落库失败。**003 表是附件队列前提**；本窗口还要靠步骤 B 的 YAML + worker 才算功能打开。不要在此步跑检查点迁移。

### 步骤 E：按服务重建（先 MCP，再 Agent，再 workbook-worker）

```bash
docker-compose --env-file deploy/environments/prod/runtime.env up -d --no-deps data-mcp
# 等 healthy
docker-compose --env-file deploy/environments/prod/runtime.env up -d --no-deps report-agent
# Agent 起来后起附件 worker（同一 report-agent 镜像）
docker-compose --env-file deploy/environments/prod/runtime.env up -d --no-deps workbook-worker
```

若改过 `runtime.env`，对应服务用 `--force-recreate`。核对 `data-mcp` / `report-agent` / `workbook-worker` 的 Image ID = 本次 inspect（后两者同为 `bjs-report-agent`），创建时间是刚才。

单服务更新务必 `--no-deps`，避免把另一个健康容器一起重建。

### 步骤 F：Nginx 与入口（本窗口默认不改 conf）

1. **不新增** `/console/`、`/api/` location。现网前缀已覆盖  
   `.../v1/ai-service/investment`、跳转后的 `.../v1/ai-service/console/`，以及前缀下的 `/api/`。
2. 核对前缀 location 仍指向 report-agent（`127.0.0.1:5129`）；`proxy_pass` 后面不接路径。
3. 可选（仅当长 SSE 有问题时）：在**现有**前缀 location 上关缓冲、`proxy_read_timeout 3600s`、`client_max_body_size 120m`，`nginx -t` 后 reload。无问题则跳过。
4. 用户入口（覆盖原计划里的 `/console/`）：

```text
https://<域名>/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/v1/ai-service/investment
```

打开后应用会 307 到同前缀下的工作台 `.../v1/ai-service/console/`；地址栏可能再改写成 bare 公网路径（复制后无法重进，属预期）。接口仍走带前缀的 `/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/api/...`。

本机直连验收可用  
`http://127.0.0.1:5129/m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/v1/ai-service/investment`；生产对外仍只走现有 Nginx 前缀。

## 5. 今天踩坑 → 生产禁令（速查）

| UAT/联调现象                                         | 生产怎么做                                                         |
| ------------------------------------------------ | ------------------------------------------------------------- |
| `docker save` 带 `\` → invalid reference format   | PowerShell 用 ``` 或单行                                          |
| 只 build `compose.yaml` 没有 mock 镜像                | 生产本来就不要 mock；附件走真实 DMP                                        |
| `start-local.ps1` / 本机 Python 起 worker           | 生产只用 compose 起 `workbook-worker`                              |
| workspaces 权限 → worker `PermissionError`         | `workspaces` 保持 uid `10001`；API 与 worker 同挂载                  |
| 空 assets 挂载 → 一页纸无 Word                          | **上线前确认宿主机两个 docx 在挂载路径**                                     |
| 只 `docker load` 容器仍旧                             | load 后必须 `up -d --no-deps` 重建                                 |
| 不带 `--env-file`                                  | 落到 test，prod 挂载不生效                                            |
| YAML 路径 prod、正文 uat                              | 核对 `current_env: prod` 与 DMP/库地址                              |
| 迁移不带 `--no-deps`                                 | 卡住等索引；生产迁移必须 `--no-deps`                                      |
| 缺 002 列就起新 Agent                                 | 先迁库，再重建 report-agent                                          |
| UAT 开了 mock + 附件                                 | 生产：**禁 mock**；附件**要开**，YAML + worker + 真实 DMP                 |
| 只建 003 表就当附件已开                                   | 必须再开 YAML 并起 worker；看 `/api/features`                         |
| 起两份 workbook-worker                              | 禁止；会抢队列与目录锁                                                   |
| `export_matched_institutions` 写进 `enabled_tools` | 禁止；该工具只给附件 worker                                             |
| bubblewrap cgroup 告警                             | 保留 seccomp/apparmor/systempaths 与 cap；字数可用其它路径，不降级 filesystem |
| 对外入口改成 bare `/console/` 或补三路径 Nginx | **本窗口不做**；入口固定带前缀的 `.../v1/ai-service/investment` |

## 6. 回退

1. 停接新任务。
2. 先停 `workbook-worker`（若已起），再用步骤 A 的回退 tar `docker load`（或给旧 Image ID 重新打 `0.1.0` 标签）。
3. 恢复目录外备份的 `compose.yaml` / YAML（去掉或关闭 `institution_workbook` 与 worker 段；`runtime.env` 若未改可不换）。
4. `up -d --no-deps` 先 data-mcp 后 report-agent；确认未再拉起 worker（或 YAML 已 `enabled: false`）。
5. Nginx 本窗口若未改 conf，回退时也不动；若只调过前缀 location 的超时/缓冲，按备份恢复即可。

已执行的 002/003 迁移**不必回滚**（可空列 + 附件队列表对旧报告无害；功能关掉后不再写入即可）。不要 `docker image prune`，直到确认新版稳定。
