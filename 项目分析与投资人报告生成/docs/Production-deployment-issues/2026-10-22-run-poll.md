# 2026-10-22 轮询把 MySQL 断连当成任务失败

**类型：改镜像**（`bjs-report-agent`）。MySQL 本身没有在这次改掉。

## 现象

`GET /m4Kp9Qx2Lv7Nc1Rd8Ws3Tf6Yb0Hz/api/runs/{run_id}` 返回 500。异常是 `pymysql.err.OperationalError: (2013, 'Lost connection to MySQL server during query')`，发生在读结果的过程中。页面把这一次 500 当成任务结束，不再继续查。

## 原因

这不是新路径引入的。同一条 `get_run` 查询，连接池在取出连接时已经 `ping(reconnect=True)`，`read_timeout` 为 60 秒。2013 出现在查询进行中，是会话中途断开。

缺陷在页面：任意一次轮询失败就中止。任务在服务端可能仍在跑。

## 修复

`apps/report_agent/src/report_agent/api/static/dev.html`：

- 正常间隔 `POLL_MS = 5000`
- 轮询 HTTP 失败或网络异常后等 `POLL_RETRY_MS = 30000` 再查
- 总窗口仍是 `POLL_MAX_MS = 40 * 60 * 1000`
- 提交失败仍然停止；只有提交成功后的轮询会继续

不要把 2013 当成「查询语句写错」或「公开页前缀导致」去改 SQL。
