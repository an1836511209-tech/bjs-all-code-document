# 工商查询名称补正与可跳过交互

问题：企查查查询无结果或公司名称非精确命中时，不应把整个 BP 任务判成失败，也不应把模糊命中的其他公司数据写进报告。

方案：校验查询名称与返回登记名称；不一致或无结果返回告警。Agent 显示可跳过的小卡片：“当前公司名称无法获取企查查数据，请提供精确名称。”用户可以填写精确名称，在同一任务重试；也可以跳过工商补数，沿用材料继续。查询本身是可选项，卡片等待选择不等于任务失败。名称和跳过决定均写入原任务记忆，避免重复询问和自动重查。

已实现：

- Data MCP 比较查询名称与登记名称（仅统一全角标点等规范形式，不做简称/相似名称兜底）。非精确命中返回 `COMPANY_NAME_NOT_EXACT`；无结果返回 `COMPANY_NOT_FOUND`。两者均为可补正告警，`data.company=null`，防止使用其他企业的工商信息。
- 一页纸工具入口把无结果、名称告警及调用异常转换成可跳过的 `registry_name` 卡片。工商工具缺失不作为启动阶段的硬依赖。卡片由程序发出，不依赖模型是否正确调用 ask_user。
- 卡片提示“当前公司名称无法获取企查查数据，请提供精确名称。”，选项为“填写精确名称”“跳过此步骤”。点填写后展开名称输入；空名称不能提交，刷新保留草稿。点跳过后不要求填写名称。
- 补正名称原样记录到当前任务，并覆盖模型可能再次提交的简称；重试仍没有结果时保留跳过入口，不自动循环。跳过决定持久化，后续意外重复调用直接返回 skipped，不再请求供应商。
- 工商信息属于可选补数，查询告警不会把 BP 任务判成失败；仅等待本次补正或跳过选择。跳过后使用材料原有信息继续画像和后续步骤，不伪造缺失登记字段。

验证：Agent 工商补正及已有交互回归通过；Data MCP 补充工具 10 项通过。真实浏览器使用模拟 MCP 验证精确名称重试、跳过不再调用、同一 task_id、空值提示与刷新保留输入，脚本异常为零。未调用真实企查查。

生效需要重启 Data MCP、Report Agent，并刷新前端。
