# 一页纸 BP 第一批：持久检查点与卡片续跑

## 实施范围

第一批在现有 Deep Agent 图上接入持久检查点、真实 interrupt/resume、成功工具结果复用和前端进度续接。固定业务节点调度与写作调用压缩留到第二批。

仅对启用检查点后新建的一页纸任务生效。投资报告和既有未建立检查点的任务保留原执行路径，不创建检查点数据库连接，不改变原 ask_user 行为。

MySQL checkpoint 使用独立 schema，由显式迁移命令建表。第一批复用已锁定 PyMySQL saver，通过项目异步适配器在线程中执行数据库操作；不在事件循环中执行同步数据库 I/O，不新增驱动。

检查点保存完整图消息与待执行节点；卡片提交 Command(resume)，不重传全量文字历史。结果复用只覆盖材料解析和只读数据查询，不缓存失败，不以缓存绕过发布校验。

## 最终行为

- 新一页纸任务使用固定 thread_id 保存完整 LangGraph 消息、工具结果和待执行节点。卡片通过 interrupt 暂停，提交后用 Command(resume) 恢复，恢复请求不再注入全量历史文字。
- 业务类型、工商补正、公开搜索、披露状态及上传提示共用规范问题载荷；question_id 基于已持久化的工具消息生成，刷新和进程重建后保持一致。
- 卡片附言与选项先保存为任务命令，回答进入图中的 HumanMessage，原目标不变。已接收而未执行的任务在启动时重排；断点已提交但命令确认未完成时，不把旧答案投给下一问题。
- 初始工具 readiness 只在新图首次执行时检查。恢复时不以已完成补数服务的 readiness 阻断后续写作。
- 材料解析和只读 MCP 结果按实际参数、材料哈希和 Skill 版本复用；失败及待补正结果不缓存。签名 URL 的签名部分不触发失效，业务查询参数仍参与指纹。
- 预算按当前生成周期累计，卡片和重启不会重置；用户等待时间不累计。仍使用现有调用上限，第一批不宣称已达到 3–4 次写作调用目标。
- 一页纸渲染 manifest 可重建发布所需状态；其发布使用 task/文件名/SHA 决定幂等对象标识，元数据重试只复用本任务相同内容的产物。投资报告继续使用原发布默认行为。
- 新卡片续跑保留计划；刷新从执行快照恢复 todo 状态。服务重启后校准 SSE 游标。恢复片段的 trace 只列新增调用，避免把历史工具误显示为重新执行。
- 新增文件锁放在工作区根目录，避免 Windows 对锁定字节的读取限制影响快照。工作区原子写入与快照共用可重入锁，防止 Windows 并发扫描临时文件时出现 FileNotFoundError/PermissionError；不改变文件权限、路径和发布规则。

## 投资报告隔离

开关默认为 false，仅 test local 配置显式开启。是否继续使用检查点以任务已建立的执行标记为准；关闭新任务开关不会让已有检查点任务退回 fresh-agent。

投资报告不构造 checkpoint saver，不接入 resumable ask_user、新问题中间件或结果缓存，不改其模型、工具选择与原始 finish/publish 调用。恢复扫描只处理一页纸执行标记；损坏的一页纸状态不会阻止 API 启动。既有一页纸任务未建立检查点，也继续原路径，不能凭已有文字历史伪造断点。

## 部署与生效

1. 独立 MySQL schema 与业务元数据库分开；本次测试使用 `bjs_report_agent_checkpoints_test`，已完成 saver 迁移，未修改投资报告业务表。
2. test local 已添加 `service.one_pager_checkpoints: true`；runtime.env 新增 `REPORT_AGENT_CHECKPOINT_DATABASE=bjs_report_agent_checkpoints_test`。
3. 重新加载 runtime.env 并重启 Report Agent，然后浏览器强制刷新；用新建的一页纸任务验证。已有投资报告任务和已有未建检查点的一页纸任务保留原执行方式。
4. 其他环境默认关闭。启用前先创建专用 schema、设置环境变量，再执行显式迁移：

```powershell
# 先按原启动说明加载环境变量，包含 REPORT_AGENT_CONFIG。
report-agent-db-migrate --checkpoints --apply
```

应用启动不建表。专用 schema 缺失或配置成业务元数据库时，一页纸新路径会报明确配置错误，不会自动退回从头执行；投资报告不依赖这项配置。

## 验证与限制

本批最终相关回归 **119 项通过**；Ruff、12 个源文件的定向 mypy、JS 语法与 diff 检查通过。工作区另外通过 12 轮、每轮 40 次/8 线程的并发压力验证。真实 MySQL 跨进程恢复与两组无头 Chrome 交互均通过，未调用真实模型或发布实际业务报告。

- 使用真实 LangChain/Deep Agent 图验证中断、图重建、工具上下文保留、选项规范化和重复恢复；本地模型/MCP 替身可计数。
- 独立 MySQL schema 验证新 Python 进程、新 saver 连接、新图和新模型恢复同一个 interrupt；材料解析与业务类型检测未重放，标签只查询一次。
- 另验收缓存失效、失败不缓存、累计预算、DB 写入取消时等待事务结束、损坏任务隔离、manifest 重建、发布幂等、投资报告不打开检查点连接与原默认发布行为。
- 无头 Chrome 验证两张卡片、刷新、附言进入当轮记忆、已完成计划保持、同任务续接、解析/标签调用计数及原有多聊天交互。

第一批是单 worker、共享持久工作区方案；不承诺跨主机调度。读 API 在返回结果尚未持久化即崩溃时仍可能重复查询。自由文本更正依赖失效、固定业务图、写作调用压缩和更完整事件日志仍在后续批次。
