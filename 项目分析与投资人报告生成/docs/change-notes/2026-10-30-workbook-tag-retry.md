# 附件复用报告标签与按标签组重新生成

日期：2026-10-30。

## 修复的行为

- 自动附件记录并复用报告实际调用 `match_investors` 的标签，支持数组或逗号分隔字符串，不再额外调用模型重新精选。DMP 无匹配或返回失败业务结果时，仍可保存经过主体/画像关联的实际入参。没有该记录的旧任务跳过自动生成，保留手选与更新标签入口，不猜测标签来源。
- 自动复用最多 10 个标签（导出契约上限），手动选择仍遵守 `max_selected_tags` 配置，超限明确提示，不截断。
- 手动重新生成绑定来源附件任务、材料上下文指纹、候选标签组指纹。更新标签后的候选保存在独立任务中，页面选择与后端校验使用同一版本，不再拿旧候选拒绝新标签。
- 同组重试复用已保存的选择；上传失败后可复用已校验的工作簿，避免再调模型或 DMP。相同参数的请求响应丢失时保留客户端请求 ID。
- 标签精选保留在用户主动更新和旧任务的手动路径中，兼容纯 JSON 与完整 Markdown JSON 代码块；无效 JSON 提示手动选择，继续验证候选范围及原文依据。
- 附件失败保留阶段与固定错误码，区分 DMP 未配置、连接失败、超时、响应格式、文件校验、上传与登记。API 不再把所有提交异常都归因于缺少迁移；日志只记录标识、阶段、错误码和异常类型。
- 前端请求 ID 增加兼容实现，支持缺少 `crypto.randomUUID` 的环境。后台状态轮询更新候选版本时会同步刷新选择入口。

## 保留的边界

独立 worker、Word 先交付、附件失败不改报告状态、首批最多 200 家、DMP 鉴权及直接/`body`/`data` 对象解包均保持原有设计。未改变主报告的机构名单裁剪、个人统计或其他匹配来源。不新增表，不需数据库迁移。

## 验证

使用本地合成数据与 HTTP 替身覆盖实际标签复用、更新标签后手选、标签组过期、请求幂等、上传重试复用、异常 JSON、DMP 失败隔离，以及三种响应包装和脏数据清洗。浏览器用例增加缺少 `randomUUID` 时更新标签并手选重试的路径。

- 附件模块 55 项、Data MCP 导出/既有投资人匹配/补充工具 58 项、原报告运行/设置/交互/下载/入口 37 项，合计 150 项通过。
- `institution-workbook.cjs` 与 `workbook-controls.cjs` 浏览器回归通过，页面脚本错误为零；更新标签后手选成功，Word 状态保持完成，开关检查不提交报告。
- `workbook-requests.cjs` 验证响应丢失后复用请求 ID、来源标签组绑定及无 `randomUUID` 的兼容实现，通过。
- Ruff、四个附件模块 Mypy、JavaScript 语法与 diff 空白检查通过。

Windows 重跑 Python 附件测试时使用短临时目录，例如 `--basetemp .runtime/wbt4`（使用新的测试专用目录）；较长的系统临时目录加上原子写入文件名可能超过 Windows 路径限制。浏览器两组用例各用全新的 fixture 服务状态，避免前组会话影响开关断言。临时 fixture 服务已停止，用户原有进程未改动。

未调用生产 DMP、真实标签模型或外部对象存储。上线需更新 Data MCP、Report Agent（含 API 和 worker）以及前端静态资源；服务重启后刷新页面加载新脚本。旧任务保留已有证据与附件，新采集的报告才具备实际匹配标签记录。
