# ADR-0003：一页纸分阶段接入持久执行恢复

- 状态：Accepted
- 日期：2026-10-29

## 决策

第一批先在现有 Deep Agent 图上接入真实检查点与 interrupt/resume，第二批再把固定业务步骤移出模型调度。完整设计见 [一页纸检查点方案](../2026-10-29-one-pager-checkpoint-resume-design.md)，第一批实际范围与部署见[修改记录](../../change-notes/2026-10-29-one-pager-checkpoints.md)。

1. 一页纸新任务显式启用；投资报告与旧任务保持原路径，绝不因没有检查点而隐式迁移或重建图。
2. 复用 MySQL 专用 schema 与已锁定的 PyMySQL saver。项目异步 adapter 使用线程调用同步 saver，避免事件循环阻塞；取消时等待线程提交/回滚完成后才释放执行锁。
3. 对每个图步骤使用同步持久性；等待用户时提交检查点并释放执行资源，不依赖 Python 调用栈。
4. 先使用工作区原子命令文件和单 worker 重建调度，不同时引入 Redis 平台。完整工具消息保存在引擎中，文字历史用于审计，不替代执行游标。
5. 共享基础设施扩展均保留原默认行为；新中间件、缓存、发布幂等和元数据去重只用于检查点一页纸任务。
6. 启动不执行 DDL；先显式迁移，再开启新任务开关。检查点任务创建后固定执行版本；新任务开关关闭不改变已有任务的恢复方式。

## 后果

优先消除卡片回答后的重新执行与已完成只读调用的重复成本。模型仍控制后续工具和写作步骤，因此第一批不承诺完整方案的模型调用目标。单主机/共享持久卷之外的任务调度、输入更正的依赖失效和模型调用压缩另行实施。
