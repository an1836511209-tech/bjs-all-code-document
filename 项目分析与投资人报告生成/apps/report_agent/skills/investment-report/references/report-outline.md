# 报告章节规范

报告是面向最终用户的交付物。报告正文中不得出现任何系统内部信息，包括但不限于：MCP 工具名、工具返回状态（success/partial/empty/failed）、警告信息（如"API 未配置""兜底生成"）、数据来源技术细节（如"系统返回""db_fallback"）等。这些信息仅供 agent 内部判断数据质量，不得写入报告正文。

报告遵循「项目打底→市场验证→对标估值→投资人匹配」核心逻辑。章节按证据可用性生成，不要求为了凑齐目录而填充内容；但有证据支持的章节必须写全必写要素，不得只写一句话就跳到下一章。

**章节生成门禁**：每个章节的每个必写要素，都必须能在 `read_material_chunk`/`read_result_chunk`/`read_evidence` 的返回原文中找到对应的具体文本。**没有证据的要素写「材料未披露」，但章节结构必须保留**——章节是固定骨架，缺的只是内容。

> 早先这里写的是"整章省略并记入 missing_items"，与 SKILL 正文的"不省略章节结构"直接冲突。
> 现在统一为：**结构固定、内容按证据填充、缺口显式标注**。审阅者要看到"这一章查过了、
> 材料没有"，而不是"这一章不存在"。

**不得为了填满章节而编造数据**：宁可写「材料未披露」，也不要写一个没有出处的数字。缺失要素在最终回复中向用户说明。

不得从参考模板复制项目名称、公司、数值、结论、案例或投资人。材料中的 `table` 类型 block 包含结构化数据时，必须以 Markdown 表格形式写入报告，不得只写成段落。


## 术语对照：产权转让 vs 增资扩股

**报告正文一律按本次业务类型选词**，不许混用——两者的资金流、稀释、税费和
决策程序完全不同，混用会让读者误判交易性质。

| 概念 | 产权（股权转让） | 增资扩股 |
|---|---|---|
| 章节名 | 转让背景与交易条件 | 增资背景与投资条件 |
| 买方 | 受让方 | 投资方 |
| 买方理由列 | 受让理由分析 | 投资理由分析 |
| 价格表述 | 转让底价 | 增资价格 / 投前估值 |
| 金额表述 | 交易对价 | 募集金额 |
| 老股东影响 | 持股比例变化 | 稀释比例 |
| 资金流向 | 付给转让方 | 进入公司 |

**判定依据**：`detect_one_pager_business_type` / 材料表述 / 用户选择。判定后整篇
沿用一套词，报告头部与投资人表头同步替换。

## 一、报告头部

标的项目全称 +「投资人匹配报告」+ 报告日期。标题通过 `title_citations` 引用 Evidence；日期使用任务运行元数据。

## 二、项目分析（报告基础盘）

目标：把卖方项目的家底讲透，形成后续所有匹配、估值的参照物。含以下子章节，每个子章节至少 1 段正文：

### （一）项目概况

必写要素（有证据时）：
- 交易标的：转让/增资的标的（如 XX 公司 X% 股权）、转让方主体及持股比例
- 标的企业基本面：成立时间、注册资本/实缴资本、注册地址、股权结构（标注实控人、本次转让方、其他股东及持股比例）
- 企业定位与政策背书：企业官方定位、核心业务边界；政府文件、政策支持、特许资质等

### （二）核心资产与业务模式

必写要素（有证据时）：
- 核心资产盘点：按业务条线分类量化资产规模（如运营类：车辆数量及自有/加盟占比；基建类：站点数量、设备功率/数量）
- 业务模式拆解：分业务说明运营方式（自营/加盟、ToG/ToC）、盈利来源、扩张逻辑
- 优劣势辩证分析：结合资产结构说明模式特点（如轻资产降低资金压力、但自有占比低影响稳定性）

### （三）财务状况

必写要素（有证据时）：
- 核心财务数据表：近 3-4 年关键指标，至少包含营业收入、净利润、利润率/亏损率。材料含 `table` block 时必须以 Markdown 表格写入
- 财务趋势分析：收入端波动趋势及驱动因素；盈利端盈亏变化、成本控制能力、盈亏平衡点预判；落脚到财务健康度与成长潜力

### （四）转让背景与交易条件

必写要素（有证据时）：
- 转让动因：转让方的退出逻辑（如战略聚焦主业、央地合作模式调整、国资布局优化等）
- 交易核心规则：定价原则（如不低于备案评估值）、股权比例对应的投资级别（财务投资/控股）、对受让方的影响（是否改变实控人、是否享有政策红利）

## 三、市场分析（赛道价值验证）

目标：证明项目所处赛道长期向好，标的企业具备增长空间。按标的企业核心业务线拆分章节，每个细分赛道一套分析：

每个细分赛道的撰写结构（有证据时）：
- 市场格局：运营主体类型（全国性/本地玩家）、竞争态势、代表性企业布局
- 存量规模：官方公开的行业总量数据（标注数据来源与时间）
- 增长预测：下游需求增速、供需缺口分析、政策驱动因素
- 市场机会：结合标的企业特点，点明其在赛道中的卡位优势与增长可能性

## 四、对标与估值参考（定价依据）

### （一）上市公司对标

有证据时写：筛选逻辑（商业模式/赛道/业务结构与标的企业匹配）、标准数据表（证券代码、证券名称、核心估值指标 PE/PB/PS、同期财务指标）、筛选说明。表格字段仅保留 MCP 实际返回的字段。

**必须标注数据期间**（如"以上为 2025 年年度数据"），写在表格正下方一行。PE/PB/PS 是时点值、财务指标是期间值，两者口径不同，不标期间读者无法判断数据新旧。数据来自哪一期就以哪一期标注，**不确定就写"数据期间以数据源披露为准"**，不许省掉这一行。

**亏损公司要说明**：PE 为负表示公司亏损，该指标不适用。表格下方补一句"PE 为负表示最近一期亏损，PE 指标不适用于该等公司"。

### （二）同类成交项目对标

有证据时写：筛选逻辑（优先北交所过往成交的同赛道/同区域项目）、标准数据表（项目名称、赛道标签、成交时间、核心估值指标、转让底价/成交价）、适配说明。

补充原则：科技类股权侧重上市公司对标；重资产/传统行业/地方国资项目侧重同类成交案例。

## 五、投资匹配分析（承上启下）

先基于项目属性提炼受让方核心要求，再按投资人类型拆解匹配逻辑：

- 总括核心条件：结合项目特点总结潜在受让方需满足的核心要求
- 分类型拆解（有证据时）：
  - 原股东与本地国资：股权增持实现控股、国资内部资源整合、政策协同
  - 产业链上下游产业资本：业务协同（如充电运营商补网点、车企补运营场景）、快速切入区域市场、垂直整合降本
  - 其他产业投资人：跨界布局需求、政策合规要求、本地资源协同
- 个人投资人侧：若 `match_investors` 返回 `counts.internal_individuals_excluded`，可一句说明匹配到的个人数量规模；**不要编造个人名单**

每一类讲清「投资人能获得什么价值」「标的企业有什么不可替代的优势」。

## 六、匹配投资人明细（核心交付成果）

- 前置声明：匹配规则、数据基础、免责说明（仅为基于公开信息的参考性名单，不代表投资方形成投资意向）
- 投资人清单表：来自 `data.candidates`（**仅机构**）；核心字段为「投资人名称」「投资人类型」「受让理由分析」。材料含 `table` block 时必须以 Markdown 表格写入
- 清单编制原则：优先级 原股东 > 同区域国资 > 直接产业链协同方 > 其他潜在投资人；理由须精准结合项目特点与投资人业务布局，禁止泛泛而谈
- 个人投资人不逐条入表；数量如需提及，使用 `counts.internal_individuals_excluded`

## 表格格式

报告中的表格使用 Markdown 表格语法，citation 标注在表格行后。格式如下：

```markdown
| 投资人名称 | 投资人类型 | 受让理由分析 |
|-----------|-----------|------------|
| 某公司 | 本地国企 | 原股东，增持可实现控股 |
<!-- cite: evidence_xxx -->
```

每行后用 `<!-- cite: evidence_xxx -->` 标注来源。若整行没有 Evidence 支持，删除该行或相应表格。
