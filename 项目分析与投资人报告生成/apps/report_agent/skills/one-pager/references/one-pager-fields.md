# 一页纸字段清单

## 字段来源

| 字段 | 一级来源 | 二级补全 |
|---|---|---|
| 项目名称 | 文档名清洗后 → 文档 → `extract_project_profile` | 缺失填「待定」 |
| 公司全称 | `extract_project_profile` → 工商 | 文档兜底 |
| 公司简称 | 文档名清洗后（去扩展名/「BP」「商业计划书」/版本号/日期） | 从全称去地名与后缀 |
| 所属区域 | `extract_project_profile` → 工商 | 文档兜底 |
| 所属行业 | `extract_project_profile` + `query_track_labels` | 文档兜底 |
| 原始简介 | LLM 从文档提炼 ≤ 100 字 | — |
| 转让底价 / 对应持股比例 / 拟募集金额 | 文档 | 缺失填「面议」/「待定」 |
| 联系人名称 | 文档 / 人工 | 缺失填「待补充」 |
| 财务数据分析 `caiwufenxi` | 文档中的财务段落 | 无则留空 |
| 非优质项目信息 `bad_info` | 文档中的风险/瑕疵段落 | 无则留空 |

## 字数建议与硬上限

| 类型 | 范围 | 谁强制 |
|---|---|---|
| 项目介绍标题 | **3-6 字** | 域模型 validator（竖排窄框 28×99pt） |
| 项目亮点标题 | **5-9 字**（以 6-7 字为宜） | 域模型 validator（横排栏位 153pt 宽） |
| 项目介绍正文 | 建议 **225-250 字** | 写作建议，不阻断渲染；不为差几字重写 |
| 项目亮点正文 | 建议 **170-185 字** | 同上 |
| 原始简介 | ≤ 100 字 | 写作约束 |
| 正文兜底上限 | 介绍 ≤400 / 亮点 ≤220 | preflight 与域模型一致，只挡极端溢出 |

> 目标范围不作为验收门槛；不得为了凑字数编造事实或反复删改。

字数按「去掉所有空白和来源标记」计，兼容 `<!-- src: ... -->`、`<!-- cite: ... -->`、`<src .../>`。

## 条件槽位与决策表

两个槽位**先判有无，再定标题**：

```
有财务数据分析 = 是  → 介绍第2个标题固定「经营分析」
有财务数据分析 = 否  → 禁止「经营分析」，自拟（不得含「财务/数据/挂牌」等看板词）
有非优质信息且用户选择展示 → 介绍第3个标题固定「风险提示」
无非优质信息或用户选择不展示 → 禁止「风险提示」，自拟（不得含「风险/隐患/警示」）
介绍第1个标题恒定「核心产品」
```

由 `check_one_pager_outline` 强制校验，违规则返回 `invalid_outline` + 逐条错误。
识别到非优质信息后，工具会先返回「展示 / 不展示」卡片，用户确认前不进入写作。识别结果 `has_risk_facts` 与展示选择 `include_risk_facts` 分离，不展示时保留内部事实记录，但不写入报告。

## 分工边界（防重复的核心）

| | 项目介绍（是什么） | 项目亮点（为什么值得投） |
|---|---|---|
| 写什么 | 定位、业务构成、产品线、应用场景 | 财务数据、资质、专利、团队、市场地位、增长 |
| 不写什么 | 成果数据（获奖数、资质认定、增长幅度） | 业务定位与构成（那是介绍的活） |
| 论证 | 只陈述，不展开价值 | 每段完成一次论证：陈述事实 → 说明为何构成竞争优势 |

**同一事实只能出现在其中一处。** `check_report` 的 `section_restatement` 规则会检测段落重合度（阈值 35%），超了判 block。

## 字段互斥（产权 vs 增资）

| 字段 | 产权 | 增资 |
|---|:---:|:---:|
| 转让底价 | ✅ 必填 | ❌ 禁止携带 |
| 对应持股比例 | ❌ 禁止携带 | ✅ 必填 |
| 拟募集金额 | ❌ 禁止携带 | ✅ 必填 |

## `missing_items` 触发条件

任何字段最终未赋值 → 写入 `missing_items`，code 用大写下划线：

```
FLOOR_PRICE_MISSING
CONTACT_MISSING
INTRO_SECTION_2_LENGTH_OUT_OF_RANGE
...
```

产权 19 个 / 增资 20 个，其中 18 个共享。详见 `domain/one_pager.py::PLACEHOLDERS_BY_BUSINESS_TYPE`。
