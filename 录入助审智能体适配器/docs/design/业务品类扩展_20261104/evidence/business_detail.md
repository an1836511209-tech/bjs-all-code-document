# 业务处理详细设计候选正文

本文件给出与需规一致的处理算法、数据职责和异常分支，供概要和详细设计正文整合。字段与状态命名属于设计建议，需与最终API契约统一，不代表现网已提供。

## 一 业务场景定位

用完整业务场景选择规则，不复制四套提取代码。产权和增资形成“产权转让预披露、产权转让正式披露、企业增资预披露、企业增资正式披露”四种配置。每份配置保存适用申请书、字段映射、字段类型、枚举、语义提示词及版本。机动车用“有纸机动车”业务类别，增加处置方式“拍卖/解体”和助审节点作为规则选择维度。

业务系统保留经办、服务机构、经理、交易审核部等用户及工作流。智能体只受理材料、提取字段、执行助审、返回差异和证据，不自动提交单据，不替代人工审核决定。机动车节点2结果应绑定单据版本及材料快照，经理和交易审核部能查看相同结果；后续单据改动应触发新执行，不能继续展示旧材料形成的审核结论为当前结果。

## 二 机动车录入流程

1. 校验调用身份、请求标识、业务类型、处置方式、附件清单、业务单据标识和是否申请拆分。生成固定的本次材料清单、规则快照和执行标识；同一标识与不同请求内容冲突时拒绝复用。
2. 接收并解析附件，文件名、调用方材料编码作为线索，正文内容作为识别依据。对PDF保存页和坐标，对Word保存段落和表格单元格定位；供预览截图使用的转换件必须可回溯原文件。
3. 匹配材料角色，形成已匹配、缺失、类型不符、无法识别列表。应传材料按处置方式和主体类型的规则条件计算，保留斜线名称之间的替代关系。
4. 按已确认的基准必传材料提取公共信息和车辆清单。公共信息含需规示例的转让方名称、地址、审批单位、任务接收方归属；车辆信息含号牌号码、审批原值（元）、品牌、型号等。全量字段以业务字典为准。
5. 对每辆车、每个字段生成来源候选，按字段优先级选择值，并保留所有候选及位置。规则直提适用于明确同名字段；语义提取适用于长文本和字段异名情况。提取结果通过类型、枚举、金额、日期和输出格式校验，校验失败列待确认。
6. 对其他材料提取车辆清单和同名字段，按车牌归集，生成车辆数量、车牌集合和字段一致性结果。返回一条公共信息及车辆数组，每个字段含录入状态和证据。
7. 若用户显式申请拆分，按原PDF页读取车牌并生成拆分件及映射。拆分结果作为独立子结果；整份提取已完成但部分页面无法拆分时保留可用提取结果，并返回拆分待处理明细，是否使整个任务失败由接口契约明示。

### 车辆归集与统计

业务唯一标识使用需规指定的车辆号牌。内部可额外生成稳定车辆行ID，以便同车字段、证据和人工确认关联。规范化仅做可逆或明确无歧义的空白处理、字母大小写和标点标准化，保存原始车牌；OCR的字母数字近形字不得自动替换为另一号牌。

设基准材料的有效车牌集合为B，某一覆盖全批次的附件集合为S。输出基准成功识别记录数、基准去重车牌数、来源成功识别记录数、来源去重车牌数、B与S的差集、S与B的差集、重复车牌及无法识别行。数量不等不直接代表车辆错误，必须结合材料覆盖范围：单车行驶证只要求其车牌属于B；全批次处置明细表才要求集合覆盖。

如基准材料缺失、无法解析，或不同候选基准清单之间发生无法解决的冲突，不计算误导性的“完全一致”。返回基准不可用原因与待确认项。VIN等字段可作为核对证据，但在需求未确认时不替代车牌作为业务唯一标识。

### 多来源选值与一致性

每条候选保存字段编码、车辆行ID或公共信息作用域、原始值、规范值、材料角色、文件ID、文件名、上传来源、优先级、页及坐标或段落/单元格、提取状态和证据片段。选值只决定展示推荐值，一致性校验仍检查规则要求的所有来源。

高优先级来源缺文件或字段未提取时，按已确认的回退策略选择下一可用来源，并输出前一来源的缺失原因，不能静默跳过。相同优先级得到不同值时列待确认，不能使用文件遍历顺序决定。字段规范化用于比较时保留币种、单位、时间点，不能把不同口径的金额或日期当成相同事实。

### 按页拆分边界

拆分默认不执行，仅当前端用户勾选并在请求中传入明确标记后运行。按原PDF的每一页输出拆分文件，名称包含确认车牌及页码；同车多页不覆盖，原页和拆分页之间保存一对一映射。

一页出现多个车牌、无车牌、车牌模糊或相互冲突时不猜测归属，保留该页并返回待处理明细。将无车牌页依据前页连续性附到某车名下、同车多页合并为一份文件，均属于需业务另行确认的策略，不作为正文已确定规则。输出需包含原文件ID、原页码、识别车牌、拆分件ID、预览或下载引用和状态。

## 三 机动车助审流程

1. 接收待审单据快照、处置方式、助审节点、已确认字段、录入阶段材料及机构阶段材料。固定输入后创建执行版本。
2. 对两方材料取并集并建立同材料候选。服务机构上传版本在同名同类型冲突时优先，原始版本及选择原因仍保留供溯源。不同车牌、不同适用范围或不同材料类型不得仅因文件同名而丢弃。
3. 解析有效材料，执行车牌校验和材料归属确认。记录被替换版本不参加本次字段判定，但可在证据审计中查看。
4. 按场景和节点选择审核规则。公共字段对比公共材料，车辆字段按车辆ID和车牌对比其证照、照片及清单行，避免跨车引用。
5. 先判规则是否适用，再校验参考材料及字段可用性，再执行确定性或语义判断。金额、比例、日期和AND/OR由确定性组件计算；模型用于语义提取、同义理解和图像识别，并必须给出材料证据。
6. 返回每字段四态、说明、规则内容、证据和统计。系统任务执行成功与审核业务通过分开表示：正常产出含“不通过”或“待确认”的结果，仍属于任务执行成功。

### 附件归并

归并应保留上传方、上传批次、文件类型、文件名、大小、内容哈希、车牌作用域和关键页摘要。先匹配同一业务材料候选，再按优先级选择有效版本。完全相同哈希可去重存储，但来源记录保留。机构重新扫描导致哈希不同但同名同类型、同车辆的材料，可以按机构优先规则替换；这需要明确同材料判定口径，不能把需规列出的哈希、大小、关键页等条件机械地写成全部同时相等。

归并结果包含有效文件、替换关系、归并理由和不能自动判定的冲突。输出用于本次审核的材料快照摘要，使重审或追溯能恢复当时实际使用版本。

### 车牌跨文件校验

按“车辆行—材料作用域—文件”生成比较关系，对同一车辆相关文件覆盖全部应比较文件对。全批次清单按集合与各单车证照归属比较，单车图片和证照按确认车牌比较。不同车辆本来车牌不同，不应在批次全局笛卡尔积下被判成错误。比较结果保留涉及文件对、原始号牌、规范号牌和定位。无法识别不能伪装为一致或不一致，应同时返回无法比较原因和待确认状态。

### 四态与缺失处理

| 条件 | 审核结果 | 说明与依据 |
| --- | --- | --- |
| 规则明确该字段在本场景无需审核 | 无需审核 | 输出对应规则标识，允许不提供审核说明 |
| 规则适用且参考文件齐备、解析成功、数据可提取，判定符合要点 | 通过 | 允许不提供说明，保留所用依据 |
| 规则适用且参考文件齐备、解析成功、数据可提取，判定违反要点 | 不通过 | 必须说明具体差异及规则要求，提供相关证据 |
| 参考文件缺失、解析失败、数据提取失败或不能可靠判断 | 待确认 | 列明文件、字段、失败原因和补充操作 |
| 转让方附属信息与行驶证产权人不一致 | 待确认 | 按需规特殊口径处理，不能直接套用一般不一致不通过 |

AND与OR分别保存各来源原子判断。参考资料齐备时，OR任一符合即通过，全部不符则不通过；AND全部符合才通过，任一明确不符则不通过。存在缺失或无法读取的规定来源时，先采用需规四态定义的完整性前置条件，列待确认；OR命中符合但另有来源缺失能否通过，需要业务规则明确例外后才能放行。

### 需规示例规则的确定性实现

初登日期：在目标字段非空且规则要求的材料齐备时，将行驶证“注册日期”、登记证“登记日期”规范为同一日期口径，逐来源对比。日期原文、规范值、来源均保留。目标为空是否不适用、应补录或待确认需字段规则确定。

年检：若可用材料明确体现年检信息，目标“是否有年检”应为是；若可用材料均未体现年检且没有交管12123“我的机动车”截图，目标应为否；有截图但解析或识别失败时不能按未上传处理。截图存在且内容应如何影响判断，以审核要点补齐。

金额和比例：需规示例为转让底价≥评估价，加价幅度≤起始价×0.03。先统一币种、金额单位和精度，用十进制定点计算，保留原始金额；缺任一依据字段或口径不同则待确认。是否适用于所有拍卖、解体和节点，需规则确认，不作为全局无条件公式。

图像：读取“相关图片附件”的实际像素，判断机动车/非机动车并识别车牌，与当前待审车辆车牌及相关附件比较。遮挡、远景、无车牌、照片多车或模型失败应分别给出不能可靠判断的原因。

## 四 产权转让与企业增资辅助录入流程

1. 接收完整场景类型和对应申请书，选择已启用规则及提示词快照。
2. 解析Word或PDF，识别正文真实业务类别及披露阶段，保留标题、章节及页码/文本片段证据。识别器先独立判断，再与请求类型比较，不能由请求类型反向决定识别结果。
3. 正文与请求不一致时中止当前录入任务并给可定位提示，不自动切换业务或阶段，不继续输出成功提取结果。通用材料不能单独证明申请书业务类别，正文不足以判定时明确返回待补材料或无法判定原因。
4. 业务和阶段匹配后，同名字段按关键词、材料类型、位置直提；长文本按语义提示词抽取关联字段。对预披露批准情况等条件字段，保存条件判断和被提取字段间的联系，避免条件未成立时补造单位名称或日期。
5. 结果返回标准字段值、置信度、原文位置和待确认项。采用原生PDF坐标或Word段落/表格位置，预览转换不丢失原文关联。置信度为辅助提示，缺证据或格式错误仍需人工确认。
6. 前端展示候选字段和待确认项，经人工核实后由业务系统保存或提交单据。产权和增资本次交付不默认执行自动助审。

四种场景应各自发布字段字典与提示词。当前材料仅给出批准情况、披露规则、公告期满安排等示例，全量业务字段尚需定义；不应在设计里虚构字段总数、全量字段编码或统一数值阈值。

## 五 证据与结果数据职责

字段值、审核结果和证据分开建模，使用引用关联。证据保存原始文件ID、材料快照、原始文件名、页码、坐标或Word结构位置、文本片段、截图对象引用和使用的规则/模型版本。拆分后新文件位置同时保留其原页映射。不能只保存短期预签名URL，否则历史任务可能因链接过期失去溯源。

公共字段和每车字段均可保存多个候选及排序；每条审核规则关联一组目标字段、参考文件和证据。统计应分别呈现任务总车辆数、字段提取成功/待确认、四态审核数量以及附件匹配数量，避免将任务完成等同业务审核全通过。

审计日志至少记录请求标识、调用身份、业务单号、执行版本、材料快照摘要、规则/提示词/模型版本、关键阶段及结果摘要。运行日志不应输出敏感证照全文、带密钥URL或未经脱敏的全部个人信息。180天审计留存与任务结果、原文件、拆分件、截图的业务留存周期分别制定。

## 六 建议测试场景

| 测试组 | 关键样例 | 预期 |
| --- | --- | --- |
| 四场景路由 | 四份正确申请书、业务互换、预/正式互换、通用材料、文件改名 | 正确场景提取；错配停止并返回证据；证据不足不猜测 |
| 材料匹配 | 别名、主体资格替代、缺失必传、非要求类型、同名错误正文 | 分别输出匹配、缺失、错误和无法识别 |
| 多车输出 | 单车、批量多车、重复车牌、清单未知车牌、单车证照覆盖 | 公共信息一份，多车行稳定关联，数量口径不混淆 |
| 多来源选值 | 高优先级缺失、值冲突、同优先级冲突、单位不同 | 保留候选和缺失提示；不静默选错来源 |
| 拆分 | 未勾选、多车多页、同车多页、无号牌页、一页多号牌 | 未授权不拆；按页命名且不覆盖；模糊页待处理 |
| 归并 | 两方完全重复、同名同类型不同扫描、不同车辆同名、单方附件 | 机构优先但不丢不同车辆，全部原始来源可追溯 |
| 审核四态 | 通过、违反规则、缺材料、解析失败、提取失败、规则不适用、主体附属信息冲突 | 严格按四态及特殊条件输出，任务成功与审核状态分离 |
| AND与OR | 全符合、部分不符、OR命中、缺一个来源、无法读取来源 | 原子证据完整；缺失分支按确认后的规则执行 |
| 业务示例 | 初登日期异名、年检分支、底价/评估价相等边界、加价3%边界 | 同义规范正确，金额用十进制且边界可复核 |
| 图像 | 正常车牌、非机动车、遮挡、无号牌、多车、损坏图片 | 依据图像内容判断；不能确定则待确认 |
| 节点和重审 | 拍卖/解体两节点、机构补件、单据修改、重触发、查看历史 | 使用正确节点规则，结果绑定正确快照和版本 |
| 非功能 | 30并发、模型时延、依赖故障、恢复、权限隔离、审计保护 | 原指标按冻结口径测量；故障可恢复；不越权取证 |
