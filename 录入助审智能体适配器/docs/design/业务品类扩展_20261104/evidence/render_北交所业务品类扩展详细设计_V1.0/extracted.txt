4 规则与提示词配置
4.1 规则解析和发布
RuleSnapshotService 先解析上下文；若显式提供 rule_config_id，验证配置存在、启用、业务类型与场景一
致；未指定时读取该场景当前发布指针。发现无配置、多个默认发布指针或跨类型引用，拒绝执行。读取规
则、材料策略、提示词及级联内容生成内容指纹，后续所有阶段只使用该快照。
JSON 配置继续供管理页面编辑，新增 draft → validated → published → retired 发布状态。编辑产生新修
订，不原地修改已发布快照；撤回发布只阻止新任务引用，在途任务保留原快照。界面仍从业务注册表生成下
拉，并展示处置模式与阶段适用范围。

4.3 提示词执行约束
模板包含适用场景、字段组、字段定义、材料角色、示例、JSON Schema、未知值策略和证据锚点要求。一
次提取一组关联信息，四种披露模板各自发布；机动车按附件类型及公共信息/车辆信息分组。模型输入使用
实体限定片段，禁止将所有车辆全文压为一个无归属上下文。
模型只能返回候选字段及锚点，后处理校验类型、枚举、范围、来源存在性和实体归属；结构不合法可有限重
试，重试次数由配置确定，耗尽后标记失败或待确认。置信度用于辅助排序和评估，阈值经标注样本校准，不
能仅靠模型自评分自动通过。模型、提示词、解析器版本记录在运行上下文中。
5 公共处理链与业务一致性校验
5.1 请求执行顺序
鉴权和项目权限 → 参数校验 → 规范请求及已有幂等记录检查
→ 已有同请求直接返回原任务及快照
→ 首次请求解析业务上下文及规则快照 → 原子幂等占位与入队 → Worker 认领
→ 下载与文件校验 → 解析或复用解析缓存 → 内容识别与材料匹配
→ 业务阶段校验 → 查询隔离后的业务结果缓存
→ 场景提取或审核 → 溯源 → 结果校验与原子提交
已验证同一输入、同一策略的业务校验结果可以缓存；无校验标识的历史结果不得跳过新业务校验。机动车审
核允许材料不齐时继续对可用信息审核并输出待确认；产权增资若缺核心申请书或业务不匹配，终止本次辅助
录入。
5.2 内容校验
识别器独立输出 detected_business_category、detected_disclosure_stage、material_type、
recognition_status 及证据。判断基于正文标题、表单章节和核心语义，文件名和调用方编码仅为线索；证据
不足时继续检索章节，不强制将通用营业执照识别为某个披露阶段。

9 任务 幂等 缓存与恢复
9.1 任务状态转换
pending 在 Worker 认领后变 processing，也可以在排队期间直接变 cancelled；Worker 领取前检查取消状
态。processing 最终变 completed、failed、cancelled 或 timeout。新增 stage 依次为 queued、
downloading、parsing、validating、extracting、checking、tracing、finalizing，审核和拆页补充
auditing、splitting 并按实际阶段裁剪。进度取已完成工作量/固定计划工作量，新增子阶段不能让已返回进
度倒退；阶段内进度是估算值，只有结果提交完成才为 1。
HTTP 等待超时只返回 pending，不把运行任务改为 timeout；执行预算耗尽才进入 timeout。轮询建议初始
2 秒并退避至 10 秒，增加抖动；具体值为设计建议，可配置。任务查询 include_details=false 只读轻量状
态，避免大批量结果反复传输。
9.2 幂等与重新触发
request_id 在 caller_id 作用域内唯一。创建幂等指纹基于规范化原始请求，包括业务、显式配置 ID 或默认选
择意图、稳定附件引用、确认字段和选择参数，不包含会因后续发布改变的实际默认规则。先检查已有幂等记
录；同指纹返回原 task_id 及其已固定快照，异指纹返回 409 IDEMPOTENCY_CONFLICT；仅首次请求解析
和锁定当前规则快照并原子创建任务。调用方传 task_id 时也核对调用方、业务和输入，不能附着到其他任

9.4 持久执行与取消
run_id 表示一次业务运行的不可变标识，技术重试或故障恢复不改变 run_id，重新助审生成新 task_id 与
run_id。Worker 消费持久队列，使用原子认领、租约心跳、内部 attempt_no 和 fencing_token，按解析、
校验、提取等阶段保存检查点。依赖故障可指数退避有限重试；参数、权限、业务错配不自动重试。租约过期
后新 Worker 可恢复，旧 Worker 用过期 fencing_token 无法提交。

消未完成外部请求，最终原子转 cancelled。若成功提交先发生，取消返回已完成；取消先提交则迟到的模型
返回不得覆盖终态。无法停止外部调用时仍禁止提交其结果，并清理暂存对象。
任务记录与入队采用仓储支持的原子机制；Redis 实现可用 Lua 或事务同时写幂等、任务元信息与 Stream，
外部对象先写不可变内容，再提交其引用。不要声称网络和外部模型实现恰好一次；允许至少一次执行，依靠
幂等结果提交保证单一有效结果。

机动车单个材料失败如不妨碍整体处理，则结果 partial 并在相关字段/规则置 pending；全任务无法解析、系
统故障或无可用输入则任务 failed。业务材料不齐与技术系统不可用在统计和告警中分开。
10.2 兼容发布
旧接口参数、状态值、results 结构保持，新增属性均可选。机动车新 API 使用 schema_version 并单独模
型，避免旧客户端把 not_applicable 反序列化失败。业务注册表、FileType 中文标签、文件名规则、LLM 分
类、MaterialResolver 和平台材料编码同步更新，不能只加一个枚举。
网关解码、业务路由和响应适配共用同一错误映射，原生与中台成功码分别治理。新 TaskType 需覆盖 Redis
序列化、状态/取消路由、网关允许列表、权限作用域和前端显示。规则快照与缓存升级使用新前缀，不批量
重写历史结果。
11 非功能与运维设计
11.1 性能验收
保留 S1 一.6 的全部目标：30 用户并发、平均响应小于 3 秒、事务成功率 100%、CPU/内存/磁盘 I/O 均小于
80%、模型 prefill 小于 2 秒、decode 至少 15 token/s。创建/查询响应与长任务全流程分别采集，测试报告
必须声明 3 秒覆盖哪些事务，并给出全流程平均值及 P95/P99，禁止以异步接收率替代全流程成功率。
测试矩阵包括单车和多车、原生 PDF 和扫描 PDF、Word、图像、混合材料、冷缓存与热缓存。批量规模、
文档页数和模型部署资源在性能基线评审中确定。容量计算依据“每任务平均页数×任务到达率×解析耗时”
和模型 token 吞吐配置 Worker、队列上限及连接池，不预设缺少实测支持的并发数。
11.2 高可用和恢复
按 99.99%可用和零单点目标，对网关、API、队列/Redis、Worker、对象存储、解析器、模型端点分别配置
冗余；负载均衡健康检查与就绪探测分离。应用内 Semaphore 不能承担跨副本总并发限制，使用中心配额或
队列调度控制模型及解析并发。
演练覆盖 API 退出、Worker 被杀、租约过期、Redis 切换、对象存储短暂不可用、模型超时、重复消费和取
消竞争。RPO/RTO、备份频率及恢复窗口随平台方案冻结，备份必须验证可恢复任务、规则快照、原始材料
和证据引用，不只恢复 Redis 键。

11.3 观测与审计

11.4 安全落点

离并控制超时。导出文件名过滤路径与控制字符。
文档内容与系统提示词分离，模型不执行正文内指令；输出经过结构、来源、字段白名单和实体边界校验。配

传输、存储加密及国密算法、审计防篡改、备份和等保要求按 S1 一.9 及交易所统一平台实现。接口本身不能

核对版本和适用条目。
12 实施 迁移与回滚
先落地统一业务注册和规则快照、结构化错误、缓存隔离、幂等及持久任务，再开发四个产权增资场景，随后
接入机动车多实体模型、录入、拆页与助审。图像模型、字段表和中台编码可并行准备，但未评审的规则不得
设为默认启用。
迁移步骤为发布兼容模型 → 新规则以 draft 导入 → 校验材料映射和字段依赖 → 样本验证 → 发布快照 → 配
置场景开关 → 小流量联调 → 分场景放量。历史任务仍使用原类型与结果模型，新任务只写新命名空间。
回滚前停止该场景接收新任务并确认在途任务处理策略，保留原文件、输入及结果。回退策略指针和应用版
本，禁止旧程序消费新 TaskType 队列；新旧队列或消费组隔离。回滚验收确认旧四类实物可调用、旧任务能
查询、未完成任务有明确状态，不能用删除新任务记录代替回滚。

merge_decisions。items 含 file_id、声明及识别类型、match_status、适用条件、识别依据和
evidence_refs；match_status 沿用 matched/missing/unexpected/ambiguous，缺失材料放在
missing_materials 且无伪造 file_id。ready=false 只表示尚未完成匹配，ready=true 表示匹配阶段完成，不
等价于材料齐全。
V05 参数为 run_id、cursor、page_size。run_id 首轮可不传，服务端固定返回的运行版本；后续必须与游标
一致。page_size 建议默认 20、范围 1 至 100，正式上限结合平台 10M 字节限制与压测发布。游标绑定
task_id、run_id、过滤条件和实体顺序并签名，过期或版本不符返回 409 STALE_TASK_VERSION。未知任
务或跨项目不可见任务统一 404 TASK_NOT_FOUND。
结果外壳 data 包含第 3.3 节结构并新增 next_cursor、has_more 及 evidence_map。evidence_map 按
evidence_id 索引本页实体及公共字段所引用的证据，包含 file_id、source_file_name、page_idx、
page_number、bbox、coordinate_space、page_width、page_height、source_content、
trace_supported、preview_url 及不可溯源原因。所有 evidence_refs 必须在本页 evidence_map 中可解
析，或给出受控证据查询引用；预览 URL 经调用方权限授权后生成。只切分 vehicles 数组；
common_fields、全任务统计及汇总属于同一固定快照，不按当前页重新计算，前端不得将多页汇总相加。
每页车辆字段 sources 引用文件预览，不返回图片 Base64；大范围证据与明细可另读受控对象引用。
pending/processing 读取结果返回 409 RESULT_NOT_READY 并包含 status；failed/cancelled/timeout
返回 409 TASK_NOT_COMPLETED 及原 error。completed 允许返回 result_status=partial，以及审核
failed/pending 结论。结果对象发布后不可变，run_id 兼作该运行结果版本。

16.7 平台和前端联调清单
平台侧新增三个 TaskType、车辆路由、材料编码、错误映射、响应大小监控及鉴权主体透传；规则/预览等未
被当前平台路由覆盖的入口需独立权限配置。不得将 x-gw-appid 或 x-gw-org 直接当成用户授权凭证。
前端按公共信息与车辆列表展示录入建议，按来源优先级显示差异；所有未识别车辆与页保留人工确认入口。
助审显示四态与缺失理由、规则依据及原页截图，区分节点和历史版本；拆页提供显式勾选动作并展示未归属
页；确认字段改变后提示旧审核结果已过期，由业务系统触发新审核。
