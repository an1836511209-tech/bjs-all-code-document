# 规则配置管理使用说明

## 功能概述

规则配置管理模块提供了一套完整的规则配置系统，用于管理"大宗实物"和"小宗实物"两种业务类型的提取规则和审核规则。

### 主要功能

- ✅ **规则配置管理**：创建、查看、更新、删除规则配置
- ✅ **提取规则管理**：定义字段提取逻辑，支持文本、单选、多选等类型
- ✅ **审核规则管理**：定义审核比对规则，支持多种审核方式
- ✅ **接口配置**：支持为提取规则配置外部接口，获取字典值等参考数据
- ✅ **Web管理界面**：提供友好的可视化管理界面
- ✅ **RESTful API**：提供完整的API接口供系统集成

## 快速开始

### 1. 安装依赖

```bash
poetry install
```

### 2. 启动服务

```bash
# 开发模式
poetry run python -m src.main

# 或使用uvicorn
poetry run uvicorn src.main:app --reload --host 0.0.0.0 --port 8580
```

### 3. 创建示例数据

```bash
# 运行示例数据创建脚本
poetry run python scripts/create_sample_rules.py
```

### 4. 访问管理界面

打开浏览器访问：
- **Web管理界面**: http://localhost:8580/web/rule-configs
- **API文档**: http://localhost:8580/docs

## 规则配置数据结构

### 规则配置 (RuleConfig)

```json
{
  "id": "uuid",
  "name": "配置名称",
  "business_type": "大宗实物",
  "description": "配置描述",
  "extraction_rules": [],
  "audit_rules": [],
  "version": "1.0.0",
  "enabled": true,
  "created_at": "2025-01-01T00:00:00Z",
  "updated_at": "2025-01-01T00:00:00Z"
}
```

### 提取规则 (ExtractionRule)

```json
{
  "id": "uuid",
  "field_name": "坐落位置",
  "field_type": "text",
  "reference_materials": ["《信息披露申请书》"],
  "extraction_logic": "从《信息披露申请书》中提取坐落位置字段的值",
  "api_config": {
    "url": "http://api.example.com/dict",
    "method": "GET",
    "params": {},
    "headers": {},
    "timeout": 30,
    "description": "接口说明"
  },
  "choices": [],
  "enabled": true,
  "notes": "备注信息"
}
```

**字段类型**:
- `text`: 文本类型
- `single_choice`: 单选类型（需要提供choices）
- `multiple_choice`: 多选类型（需要提供choices）

### 审核规则 (AuditRule)

```json
{
  "id": "uuid",
  "field_name": "坐落位置",
  "audit_materials": [
    "《信息披露申请书》",
    "《房屋所有权证》"
  ],
  "audit_material_fields": [
    "《房屋所有权证》-房屋坐落",
    "《信息披露申请书》-坐落位置"
  ],
  "audit_content": "校验系统字段值是否与审核材料字段内容一致",
  "comparison_method": "字段值比对",
  "auto_process_rules": [
    "若无法成功提取对应字段中的任一数值或无法做出判断，则审核结果为待确认",
    "若可正常提取对应全部字段值，且符合上述审核要求，则审核通过",
    "若可正常提取对应全部字段值，但不符合上述审核要求，则审核不通过"
  ],
  "enabled": true,
  "notes": "备注信息"
}
```

## Web界面使用

### 1. 配置列表页面

访问 `/web/rule-configs`，可以看到所有规则配置的列表：

- 查看配置的基本信息（名称、业务类型、规则数量等）
- 点击"查看"按钮进入详情页面
- 点击"删除"按钮删除配置
- 点击"新建配置"创建新的规则配置

### 2. 创建规则配置

1. 点击"新建配置"按钮
2. 填写配置名称、业务类型和描述
3. 点击"创建配置"

### 3. 管理提取规则

在配置详情页面：

**添加提取规则**:
1. 点击"添加提取规则"按钮
2. 填写表单：
   - 字段名称：要提取的字段名
   - 字段类型：选择文本、单选或多选
   - 参考材料：用逗号分隔，如"《申请书》,《证书》"
   - 提取逻辑：用自然语言描述提取逻辑
   - 选项列表：如果是单选或多选，填写选项（逗号分隔）
   - 接口配置：如果需要调用接口获取数据，填写接口信息
   - 备注：可选的备注信息
3. 点击"添加"

**删除提取规则**:
- 展开规则详情，点击"删除"按钮

### 4. 管理审核规则

在配置详情页面：

**添加审核规则**:
1. 点击"添加审核规则"按钮
2. 填写表单：
   - 审核字段名称：要审核的字段名
   - 审核材料：用逗号分隔
   - 审核材料字段：每行一个字段，格式如"《证书》-字段名"
   - 审核内容：描述审核的具体内容
   - 比对方式：如"字段值比对"、"内容审核"等
   - 自动处理规则：每行一条规则，描述不同情况的处理方式
   - 备注：可选的备注信息
3. 点击"添加"

**删除审核规则**:
- 展开规则详情，点击"删除"按钮

## API使用

### 规则配置API

**创建规则配置**
```http
POST /api/v1/rule-configs
Content-Type: application/json

{
  "name": "配置名称",
  "business_type": "大宗实物",
  "description": "配置描述"
}
```

**获取配置列表**
```http
GET /api/v1/rule-configs?business_type=大宗实物&enabled=true
```

**获取配置详情**
```http
GET /api/v1/rule-configs/{config_id}
```

**更新配置**
```http
PUT /api/v1/rule-configs/{config_id}
Content-Type: application/json

{
  "name": "新名称",
  "enabled": false
}
```

**删除配置**
```http
DELETE /api/v1/rule-configs/{config_id}
```

### 提取规则API

**添加提取规则**
```http
POST /api/v1/rule-configs/{config_id}/extraction-rules
Content-Type: application/json

{
  "field_name": "坐落位置",
  "field_type": "text",
  "reference_materials": ["《信息披露申请书》"],
  "extraction_logic": "提取逻辑描述",
  "api_config": {
    "url": "http://api.example.com",
    "method": "GET"
  }
}
```

**更新提取规则**
```http
PUT /api/v1/rule-configs/{config_id}/extraction-rules/{rule_id}
```

**删除提取规则**
```http
DELETE /api/v1/rule-configs/{config_id}/extraction-rules/{rule_id}
```

### 审核规则API

**添加审核规则**
```http
POST /api/v1/rule-configs/{config_id}/audit-rules
Content-Type: application/json

{
  "field_name": "坐落位置",
  "audit_materials": ["《申请书》", "《证书》"],
  "audit_material_fields": ["《证书》-坐落"],
  "audit_content": "审核内容描述",
  "comparison_method": "字段值比对",
  "auto_process_rules": ["规则1", "规则2"]
}
```

**更新审核规则**
```http
PUT /api/v1/rule-configs/{config_id}/audit-rules/{rule_id}
```

**删除审核规则**
```http
DELETE /api/v1/rule-configs/{config_id}/audit-rules/{rule_id}
```

## 数据存储

规则配置数据以JSON格式存储在 `data/rule_configs/` 目录下：

```
data/
└── rule_configs/
    ├── {config_id_1}.json
    ├── {config_id_2}.json
    └── ...
```

每个配置文件包含完整的配置信息，包括所有提取规则和审核规则。

## 最佳实践

### 1. 命名规范

- **配置名称**：使用"业务类型-具体场景"的格式，如"大宗实物-房产交易规则"
- **字段名称**：使用清晰的中文名称，与业务系统保持一致
- **材料名称**：使用书名号《》包裹，如"《信息披露申请书》"

### 2. 提取逻辑描述

提取逻辑应该：
- 使用自然语言清晰描述
- 明确指出从哪个材料中提取
- 说明提取的具体字段
- 如有特殊处理逻辑，详细说明

示例：
```
从《信息披露申请书》的"转让方信息"部分提取"转让方名称"字段的值，
如果是企业则提取企业全称，如果是个人则提取姓名
```

### 3. 审核规则设计

审核规则应该：
- 明确列出所有需要的审核材料
- 详细描述审核的具体内容
- 提供完整的自动处理规则，覆盖所有可能的情况
- 包含待确认、通过、不通过三种结果的处理逻辑

### 4. 接口配置

为提取规则配置接口时：
- 确保接口URL正确且可访问
- 设置合理的超时时间
- 提供清晰的接口说明
- 考虑接口的容错处理

## 故障排查

### 问题：无法访问Web界面

**解决方法**:
1. 确认服务已启动：`http://localhost:8580/health`
2. 检查端口是否被占用
3. 查看日志文件确认错误信息

### 问题：创建配置失败

**解决方法**:
1. 检查 `data/rule_configs/` 目录是否存在且有写入权限
2. 确认业务类型选择正确
3. 查看日志了解具体错误

### 问题：删除配置后文件仍存在

**解决方法**:
- 检查文件系统权限
- 手动删除对应的JSON文件

## 技术架构

```
规则配置模块
├── 数据模型 (src/schemas/rule_config.py)
│   ├── RuleConfig: 规则配置
│   ├── ExtractionRule: 提取规则
│   └── AuditRule: 审核规则
│
├── 业务逻辑 (src/services/rule_config_service.py)
│   └── RuleConfigService: 规则配置服务
│
├── API端点 (src/api/v1/endpoints/)
│   ├── rule_config.py: RESTful API
│   └── rule_config_web.py: Web界面路由
│
├── 前端模板 (src/templates/rule_config/)
│   ├── list.html: 配置列表页
│   ├── create.html: 创建配置页
│   └── detail.html: 配置详情页
│
└── 数据存储 (data/rule_configs/)
    └── *.json: JSON配置文件
```
