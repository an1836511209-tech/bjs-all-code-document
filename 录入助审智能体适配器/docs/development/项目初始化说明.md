## 📦 Git仓库配置

### 分支策略（Gitflow）

```
main (生产环境)
  ├── develop (开发环境)
  │   ├── feature/xxx (功能开发)
  │   ├── feature/yyy (功能开发)
  │   └── ...
  ├── release/x.x.x (发布准备)
  └── hotfix/xxx (紧急修复)
```

#### 分支说明

1. **main分支**
   - 生产环境分支
   - 只能从release或hotfix分支合并
   - 每次合并都应该打tag标记版本号

2. **develop分支**
   - 开发环境分支
   - 所有功能开发的基础分支
   - 保持可部署状态

3. **feature分支**
   - 功能开发分支
   - 从develop分支创建
   - 命名格式：`feature/功能名称`
   - 开发完成后合并回develop

4. **release分支**
   - 发布准备分支
   - 从develop分支创建
   - 命名格式：`release/版本号`
   - 完成后合并到main和develop

5. **hotfix分支**
   - 紧急修复分支
   - 从main分支创建
   - 命名格式：`hotfix/修复内容`
   - 完成后合并到main和develop

### 提交规范（Conventional Commits）

提交信息格式：`<type>(<scope>): <subject>`

**Type类型**:
- `feat`: 新功能
- `fix`: 修复bug
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 重构代码
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建/工具相关

**示例**:
```bash
feat(extraction): 添加流式字段提取功能
fix(audit): 修复规则引擎空指针异常
docs(api): 更新接口文档说明
chore(deps): 升级FastAPI到0.104版本
```

  main                 # 生产环境分支

## 🚀 开发环境准备

### 1. 环境要求

**系统要求**:
- 操作系统：Windows 10/11, Linux, macOS
- Python：3.10 或更高版本
- PostgreSQL：13 或更高版本
- Redis：6 或更高版本

**开发工具**:
- Git 2.0+
- Poetry（Python依赖管理）
- Docker（可选，用于容器化部署）

### 2. 安装依赖

```bash
# 克隆项目
git clone https://gitee.com/momomomom/bjs_luruzhushen.git
cd bjs_luruzhushen

# 切换到develop分支
git checkout develop

# 安装Poetry（如果未安装）
# Windows (PowerShell)
(Invoke-WebRequest -Uri https://install.python-poetry.org -UseBasicParsing).Content | python -

# Linux/macOS
curl -sSL https://install.python-poetry.org | python3 -

# 安装项目依赖
poetry install

# 激活虚拟环境
poetry shell
```

### 3. 配置环境变量

```bash
# 复制环境变量模板
cp .env.example .env

# 编辑.env文件，配置以下关键项：
# - DATABASE_URL: 数据库连接字符串
# - REDIS_URL: Redis连接地址
# - SECRET_KEY: JWT密钥
# - LLM_API_KEY: LLM服务API密钥
```

### 4. 初始化数据库

```bash
# 创建数据库（PostgreSQL）
createdb bjs_luruzhushen

# 运行数据库迁移
poetry run alembic upgrade head
```

### 5. 启动服务

```bash
# 启动开发服务器
poetry run uvicorn src.main:app --reload --host 0.0.0.0 --port 8580

# 启动Celery Worker（新终端）
poetry run celery -A src.core.celery worker --loglevel=info

# 启动Celery Beat（定时任务，可选）
poetry run celery -A src.core.celery beat --loglevel=info
```

### 6. 验证安装

访问以下地址验证服务是否正常：

- **API文档**: http://localhost:8580/docs
- **ReDoc文档**: http://localhost:8580/redoc
- **健康检查**: http://localhost:8580/health

## 📝 开发流程

### 1. 创建功能分支

```bash
# 从develop分支创建新功能分支
git checkout develop
git pull origin develop
git checkout -b feature/文件质量检测
```

### 2. 编写代码

按照项目结构和代码规范编写代码，确保：
- 遵循PEP 8规范
- 添加类型注解
- 编写单元测试
- 添加必要的文档注释

### 3. 代码检查

```bash
# 格式化代码
poetry run black src/ tests/
poetry run isort src/ tests/

# 代码检查
poetry run flake8 src/ tests/
poetry run mypy src/

# 运行测试
poetry run pytest
```

### 4. 提交代码

```bash
# 添加变更
git add .

# 提交（遵循提交规范）
git commit -m "feat(quality): 实现文件清晰度检测功能"

# 推送到远程
git push origin feature/文件质量检测
```

### 5. 合并到develop

```bash
# 切换到develop分支
git checkout develop
git pull origin develop

# 合并功能分支
git merge --no-ff feature/文件质量检测

# 推送到远程
git push origin develop

# 删除功能分支（可选）
git branch -d feature/文件质量检测
git push origin --delete feature/文件质量检测
```

## 💡 常见问题

### Q1: 如何添加新的API接口？

1. 在 `src/api/v1/endpoints/` 下创建或修改对应的路由文件
2. 在 `src/schemas/` 下定义请求/响应模型
3. 在 `src/services/` 下实现业务逻辑
4. 在 `tests/` 下添加测试用例
5. 更新API文档

### Q2: 如何修改数据库表结构？

```bash
# 修改src/models/下的模型文件

# 生成迁移脚本
poetry run alembic revision --autogenerate -m "描述变更内容"

# 应用迁移
poetry run alembic upgrade head
```

### Q3: 如何集成新的LLM服务？

1. 在 `src/services/llm/` 下创建新的LLM类
2. 继承 `BaseLLM` 基类
3. 实现 `generate()` 和 `stream_generate()` 方法
4. 在配置中添加对应的环境变量
5. 更新LLM工厂类

### Q4: 如何添加新的业务类型规则？

1. 通过规则配置接口创建新规则
2. 定义提取字段和提取逻辑
3. 定义审核规则和审核要点
4. 激活规则并测试
