# 溯源系统优化 V2 - 修改日志

## 修改时间
2025-11-24

## 修改概述
针对溯源系统存在的"跨块/跨页匹配困难"和"LLM 依赖过重"问题进行全面优化，引入全文拼接匹配算法和多区域高亮支持。

---

## 1. 数据模型升级

### 文件：`src/services/llm/models.py`

#### 新增 Region 类
```python
class Region(BaseModel):
    """溯源区域模型 - 表示某一页上的一个矩形区域"""
    page_idx: int
    page_number: int
    bbox: List[float]
    text_segment: Optional[str]  # 可选，仅用于调试
```

#### 升级 TracingResult
- **新增字段**：`regions: Optional[List[Region]]` - 支持多区域/跨页溯源
- **保留字段**：`page_idx`, `page_number`, `bbox` - 兼容旧版代码（标记为 Deprecated）
- **新增匹配类型**：`match_type` 新增 `"anchor_stitch"` 值

---

## 2. 文本匹配算法升级

### 文件：`src/services/llm/text_matcher.py`

#### 新增全文拼接匹配算法 `_global_anchor_match`

**核心逻辑**：
1. **虚拟纸带构建**：将文档所有页面的所有文本块按顺序拼接成一个长字符串。
2. **字符映射表**：构建 `char_map`，记录每个字符对应的 `(page_idx, bbox)`。
3. **定位查找**：在长字符串中查找目标文本（支持归一化和容错）。
4. **坐标回溯**：根据查找到的位置，从映射表中提取所有涉及的 bbox。
5. **按页分组**：将 bbox 按 `page_idx` 分组，同页的 bbox 合并为一个大框。
6. **返回 Region 列表**：支持跨页、跨块、跨行的溯源。

**优势**：
- 彻底解决跨块/跨行/跨页的文本匹配问题
- 完全基于代码算法，无需调用 LLM
- 预计拦截 90%+ 原本需要 LLM 兜底的请求

#### 匹配策略优化

**匹配优先级**：
1. **Level 1**: 全文拼接匹配（`anchor_stitch`）- 仅对长文本（>5字符）启用
2. **Level 2**: 精确匹配（`exact`）- 单块内完全匹配
3. **Level 3**: 模糊匹配（`fuzzy`）- 单块内相似度匹配
4. **Level 4**: LLM 溯源（`llm`）- 最后兜底

## 3. LLM 溯源 Agent 升级

### 文件：`src/services/llm/client.py`

#### TracingAgent 解析逻辑更新

- **支持新格式**：解析 LLM 返回的 `regions` 数组
- **兼容旧格式**：如果 LLM 返回单个 `page_idx` 和 `bbox`，自动转换为 Region 列表
- **状态检查**：支持 `status: "not_found"` 的明确返回
- **错误处理**：增强对无效坐标的验证

**LLM 返回示例**：
```json
{
    "tracing_result": {
        "status": "success",
        "regions": [
            {"page_idx": 0, "bbox": [100, 200, 500, 230]},
            {"page_idx": 1, "bbox": [100, 50, 300, 80]}
        ],
        "match_type": "exact"
    }
}
```

## 4. PDF 高亮生成优化

### 文件：`src/services/extraction/service.py`

#### 高亮逻辑重构

**主要变更**：
1. **多区域适配**：
   - 优先读取 `tracing_result.regions`
   - 如果为空，兼容旧版 `tracing_result.bbox`

2. **同页多框支持**：
   - 按页码分组 bbox
   - 同一页面的多个框在同一张底图上绘制

3. **跨页合并**：
   - 检测涉及多个页码时，自动标记为跨页
   - 调用 `_generate_merged_highlight` 生成垂直拼接的长图

#### 新增方法 `_generate_multi_bbox_highlight`

**功能**：在同一页面上绘制多个 bbox

**处理策略**：
- 优先调用高亮器的 `highlight_multiple_regions_single_page` 方法（如果支持）
- 降级方案：合并所有 bbox 为一个大框

#### 升级方法 `_generate_merged_highlight`

**功能增强**：
- 支持同页多框（按页分组后，每页绘制所有 bbox）
- 单页时直接返回，避免重复上传
- 多页时垂直拼接，中间添加分隔线

## 5. 兼容性保证

### 向后兼容
- **旧字段保留**：`TracingResult` 保留 `page_idx`, `page_number`, `bbox` 字段
- **自动转换**：旧代码仍可使用单个 bbox，新代码优先使用 `regions`
- **降级方案**：如果 regions 为空，自动构造单个 Region

### 前向兼容
- 新增的 `Region` 和 `regions` 字段完全可选
- 不影响现有的提取流程

## 7. 测试建议

### 测试场景

1. **跨行文本**：
   - 输入：文本在 OCR 结果中被切分为多行
   - 预期：全文拼接匹配成功，返回多个 Region

2. **跨页表格**：
   - 输入：表格内容跨越 2-3 页
   - 预期：返回多页 Region，生成垂直拼接的高亮图

3. **同页多个匹配**：
   - 输入：同一字段在同一页出现多次
   - 预期：返回多个 Region（同页），高亮图显示所有位置

4. **短文本保护**：
   - 输入：2-3 个字符的短文本
   - 预期：跳过全文拼接匹配，直接使用精确匹配（避免误匹配）

5. **LLM 兜底**：
   - 输入：OCR 严重错误，代码匹配全部失败
   - 预期：LLM 返回多 regions，正常解析
