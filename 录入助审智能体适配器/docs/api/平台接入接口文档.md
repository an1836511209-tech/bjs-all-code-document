## 1. 概述

### 1.1 服务地址

| 环境 | Base URL |
|------|----------|
| 测试/联调（外部访问） | `http://example.com:7580/api/platform/v1` |
| 生产 | 以实际部署为准 |

说明：
- 本文档面向**外部厂商跨机调用**。示例使用宿主机对外端口 **7580**（Docker 映射 `-p 7580:8580`）。
- **8580** 为容器内监听端口，外部请勿直接使用。
- 实际联调/生产主机地址以交付环境为准；下文 curl 中的主机仅作示例。

### 1.2 接口清单

中文名：动词（平台限定词）+ 业务对象，以「服务」结尾，不超过 50 个中文字。  
英文名：与中文对应的动宾词组，PascalCase，以限定前缀开头、以 `Srv` 结尾，不超过 50 个字符，无下划线/数字/特殊符号。

| 序号 | 接口中文名 | 接口英文名 | 方法 | 路径 |
|------|------------|------------|------|------|
| 1 | 验证文件质量服务 | ValidateFileQualitySrv | POST | `/file/quality-check` |
| 2 | 查询文件分类服务 | InquiryFileClassificationSrv | POST | `/file/classification` |
| 3 | 查询字段信息服务 | InquiryFieldInfoSrv | POST | `/extraction/sync` |
| 4 | 验证字段规则服务 | ValidateFieldRuleSrv | POST | `/audit/sync` |
| 5 | 查询任务状态服务 | InquiryTaskStatusSrv | GET | `/task` |
| 6 | 更新任务取消服务 | UpdateTaskCancelSrv | POST | `/task/cancel` |

### 1.3 通用约定

#### 数据类型规范

参数表「数据类型」列仅使用下列取值：

| 数据类型 | 说明 |
|----------|------|
| VARCHAR2(n) | 变长字符串，须标明长度 n；n 最大 4000 |
| CLOB | 大文本。当字符串长度需求超过 4000 时使用 |
| NUMBER | 数值（含整数、小数） |
| DATE | 日期时间 |
| BOOLEAN | 布尔值 |
| 数据实体 | 单个对象（嵌套结构） |
| 实体集合 | 数组/列表（元素可为基本类型或数据实体） |

参数表列顺序统一为：**参数名 | 中文说明 | 数据类型 | …**

#### 请求头

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| Content-Type | 内容类型。JSON 接口填 `application/json` | VARCHAR2(128) | 是 |
| X-Provider-Api-Key | 提供方访问密钥。仅当服务端配置了 `PLATFORM_GW_PROVIDER_API_KEY` 时必填 | VARCHAR2(128) | 条件 |

平台标准请求头（如 `x-gw-appid`、`x-gw-token` 等）由**消费方 ↔ 平台**处理；提供方本系统**不校验、不赋权**这些头。

#### 统一响应外壳（Body）

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| code | 业务 HTTP 语义状态码。成功一般为 `200` | NUMBER |
| message | 响应消息。成功多为 `success`；超时未完成可为「任务处理中，请稍后查询结果」 | VARCHAR2(500) |
| trace_id | 请求追踪 ID，用于日志排查 | VARCHAR2(64) |
| timestamp | 响应时间戳（UTC，ISO 8601） | DATE |
| data | 业务数据；成功时返回。具体为数据实体或实体集合，见各接口 | 数据实体 / 实体集合 |
| error | 错误信息；失败时返回（见下表） | 数据实体 |

#### error 对象

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| error_code | 业务错误码，如 `VALIDATION_ERROR`、`FILE_001` | VARCHAR2(64) |
| error_message | 错误详细说明（中文） | VARCHAR2(1000) |
| details | 字段级错误列表，可为空 | 实体集合 |
| details[].field | 出错字段名 | VARCHAR2(128) |
| details[].message | 该字段的中文错误说明 | VARCHAR2(500) |

#### 平台业务响应头（提供方写入）

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| x-gw-biz-code | 提供方业务码。成功为 `PS-001`；校验失败为 `PV-*`；认证失败为 `PA-*`；内部异常为 `PI-*`；未归类为 `PO-*` | VARCHAR2(32) |
| x-gw-biz-msg | 业务描述。默认 ASCII 安全文案；完整中文见 Body | VARCHAR2(500) |

> 平台生成的 `x-gw-instance` / `x-gw-return-code` / `x-gw-return-msg` 仅经平台调用时出现；直连提供方时没有属正常。

#### 错误响应示例

```json
{
  "code": 400,
  "message": "Bad Request",
  "trace_id": "trace_xxxxxxxxxxxx",
  "timestamp": "2026-09-13T09:00:00Z",
  "error": {
    "error_code": "VALIDATION_ERROR",
    "error_message": "请求参数验证失败",
    "details": [
      {
        "field": "files",
        "message": "files字段不能为空"
      }
    ]
  }
}
```

对应响应头示例：

```http
HTTP/1.1 400 Bad Request
x-gw-biz-code: PV-001
x-gw-biz-msg: Request parameter validation failed
Content-Type: application/json
```

## 3. 文件质量检测

### 3.1 基本信息

| 项 | 说明 |
|----|------|
| 接口中文名 | 验证文件质量服务 |
| 接口英文名 | ValidateFileQualitySrv |
| 方法 / 路径 | `POST /api/platform/v1/file/quality-check` |
| Content-Type | `application/json` |
| 同步异步 | 同步 |

**接口描述**：对附件做清晰度、分辨率、遮挡等质量检测。支持通过 URL 或 Base64 传入文件。

### 3.2 请求参数

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| files | 待检测的文件列表，至少 1 个 | 实体集合 | 是 |
| request_id | 请求唯一标识，用于幂等与日志关联 | VARCHAR2(64) | 否 |

#### files[] 元素

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| file_url | 文件 URL 地址。与 `file_stream` 二选一，必须提供其中一个 | VARCHAR2(2000) | 条件 |
| file_stream | 文件流（Base64 或 Data URI）。与 `file_url` 二选一 | CLOB | 条件 |
| file_name | 文件名称（含扩展名） | VARCHAR2(255) | 是 |
| file_type | 业务文件类型，见本接口业务字典；未传时响应回显为 null | VARCHAR2(100) | 否 |

### 3.3 响应参数

#### 外壳字段

见「1.3 统一响应外壳」。其中 `data` 为**实体集合**。

#### data[] 元素

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| file_id | 文件 ID（本次检测生成） | VARCHAR2(64) |
| file_name | 文件名称 | VARCHAR2(255) |
| file_type | 业务文件类型，见本接口业务字典 | VARCHAR2(100) |
| file_url | 文件 URL；若请求走 Base64 可能为空 | VARCHAR2(2000) |
| quality_status | 综合质量状态，见本接口业务字典 | VARCHAR2(32) |
| quality_result | 质量检测详细结果 | 数据实体 |
| message | 检测结果中文消息，如「文件质量校验通过」 | VARCHAR2(500) |

#### quality_result 对象

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| clarity | 清晰度检测结果，见本接口业务字典（质量状态） | VARCHAR2(32) |
| clarity_score | 清晰度分数（融合评分，越高越好） | NUMBER |
| resolution | 分辨率检测结果，见本接口业务字典（质量状态） | VARCHAR2(32) |
| resolution_value | 分辨率值，如 `1920x1080` | VARCHAR2(32) |
| occlusion | 遮挡检测结果，见本接口业务字典（质量状态） | VARCHAR2(32) |
| occlusion_score | 遮挡分数（0~1，越低越好） | NUMBER |

### 3.4 请求示例

```bash
curl -X POST "http://example.com:7580/api/platform/v1/file/quality-check" \
```

## 4. 文件分类

### 4.1 基本信息

| 项 | 说明 |
|----|------|
| 接口中文名 | 查询文件分类服务 |
| 接口英文名 | InquiryFileClassificationSrv |
| 方法 / 路径 | `POST /api/platform/v1/file/classification` |
| Content-Type | `application/json` |
| 同步异步 | 同步；超时后任务继续后台执行，可用任务查询接口拉取结果 |

**接口描述**：对上传文件做智能分类，返回 `file_type` 枚举值。若处理超过 `timeout`，返回 `status=pending` 与 `task_id`。

### 4.2 请求参数

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| files | 待分类的文件列表，至少 1 个 | 实体集合 | 是 |
| task_id | 任务 ID；用于继续未完成任务或指定任务标识 | VARCHAR2(64) | 否 |
| timeout | 同步等待超时时间（毫秒），默认 `300000`，最小 `1000` | NUMBER | 否 |
| request_id | 请求唯一标识，用于幂等与日志关联 | VARCHAR2(64) | 否 |

#### files[] 元素

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| file_url | 文件 URL 地址 | VARCHAR2(2000) | 是 |
| file_name | 文件名称 | VARCHAR2(255) | 是 |

### 4.3 响应参数

#### data 对象

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| request_id | 请求 ID | VARCHAR2(64) |
| task_id | 任务 ID；超时未完成时用于后续查询 | VARCHAR2(64) |
| status | 任务整体状态，见本接口业务字典 | VARCHAR2(32) |
| results | 文件分类结果列表 | 实体集合 |
| total_files | 总文件数 | NUMBER |
| success_count | 无异常完成的文件数 | NUMBER |
| failed_count | 异常兜底为 `other_documents` 的文件数 | NUMBER |
| processing_time_ms | 处理耗时（毫秒） | NUMBER |

#### results[] 元素

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| file_name | 文件名称 | VARCHAR2(255) |
| file_url | 文件 URL 地址 | VARCHAR2(2000) |
| file_type | 分类后的业务文件类型枚举值，见本接口业务字典 | VARCHAR2(100) |

## 5. 同步字段提取

### 5.1 基本信息

| 项 | 说明 |
|----|------|
| 接口中文名 | 查询字段信息服务 |
| 接口英文名 | InquiryFieldInfoSrv |
| 方法 / 路径 | `POST /api/platform/v1/extraction/sync` |
| Content-Type | `application/json` |
| 同步异步 | 同步；超时后任务继续后台执行，可用任务查询接口拉取结果 |

**接口描述**：按业务类型与规则配置，从多个附件中提取字段，并返回溯源信息。若处理超过 `timeout`，返回 `status=pending` 与 `task_id`。

### 5.2 请求参数

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| extraction_type | 提取类型（业务类型），见本接口业务字典 | VARCHAR2(64) | 是 |
| files | 待提取文件列表（通常至少 1 个） | 实体集合 | 是 |

## 7. 查询任务状态

### 7.1 基本信息

| 项 | 说明 |
|----|------|
| 接口中文名 | 查询任务状态服务 |
| 接口英文名 | InquiryTaskStatusSrv |
| 方法 / 路径 | `GET /api/platform/v1/task` |
| 同步异步 | 同步 |

**接口描述**：查询字段提取、文件分类或规则审核任务的进度与结果。常用于同步接口超时后的结果拉取。

### 7.2 查询参数

| 参数名 | 中文说明 | 数据类型 | 必填 |
|--------|----------|----------|------|
| task_id | 任务 ID（提取/分类/审核同步接口返回的 task_id） | VARCHAR2(64) | 是 |
| type | 任务类型，见本接口业务字典。不传时按实现自动解析 | VARCHAR2(32) | 否 |
| include_details | 是否包含详细结果，默认 `true` | BOOLEAN | 否 |

### 7.3 响应参数

#### data 对象

| 参数名 | 中文说明 | 数据类型 |
|--------|----------|----------|
| task_id | 任务 ID | VARCHAR2(64) |
| task_type | 任务类型，见本接口业务字典 | VARCHAR2(32) |
| status | 任务状态，见本接口业务字典 | VARCHAR2(32) |
| progress | 进度（0~1） | NUMBER |
| status_message | 当前阶段中文描述，如「正在解析文件...」 | VARCHAR2(1000) |
| result | 任务结果；结构随 `task_type` 变化（提取结果或审核结果） | 数据实体 |
| total_count | 总任务数（提取=总字段数，分类=总文件数，审核=总规则数） | NUMBER |
| completed_count | 已完成数（提取=成功字段数，分类=已处理文件数，审核=通过规则数） | NUMBER |
| error_message | 失败时的错误信息 | VARCHAR2(1000) |
| created_at | 创建时间（ISO 8601） | DATE |
| updated_at | 更新时间（ISO 8601） | DATE |
| completed_at | 完成时间（ISO 8601），未完成时为空 | DATE |

## 10. 备注

1. 字段名一律使用 **snake_case**（如 `file_url`、`request_id`），与旧版 camelCase 文档示例不同。  
2. 数据类型仅支持：`VARCHAR2(n)`、`NUMBER`、`DATE`、`BOOLEAN`、`数据实体`、`实体集合`、`CLOB`；`VARCHAR2` 须标明长度，超过 4000 时使用 `CLOB`。  
3. JSON 响应体积超过约 10MiB 时，平台入口会替换为 `PI-001` 错误，不截断半截 JSON。  
4. 各接口涉及的封闭码表见该接口末尾「业务字典」；第 2 章仅作索引。  
5. 更完整的接入策略、白名单与联调待确认项，见《北交所API统一管控平台接入说明》。
